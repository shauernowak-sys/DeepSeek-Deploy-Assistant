## D1 空 `homeDir` 摧毁诊断报告

**现象（修复前实测）**

```
sanitize('hello world', '')
=> "<user><<user>u<user>s<user>e<user>r<user>><user>h<user>...
```

**根因**：`out.replaceAll(homeDir, '<user>')` 在 `homeDir === ''` 时等价于"在每个字符之间插值"。`diag-service` 传入 `process.env.USERPROFILE ?? ''`，一旦该变量为空（服务会话、被剥离环境变量启动、精简镜像），整份报告变成乱码，且**用户目录再也无法被替换**。

**修复**（`report.ts`）

```ts
// 空/过短的 homeDir 直接跳过路径替换：replaceAll('') 会把占位符插进每个字符之间。
const home = homeDir.trim().replace(/[\\/]+$/, '');
if (home.length >= 3) {
  const user = home.split(/[\\/]/).pop() ?? '';
  const variants = new Set([
    home,
    home.replace(/\\/g, '/'),
    home.replace(/\//g, '\\'),
    home.replace(/\\/g, '\\\\'), // JSON 段里是二次转义
  ]);
  for (const variant of variants) {
    if (variant.length >= 3) out = out.split(variant).join(USER_PLACEHOLDER);
  }
  if (user.length >= 3) out = out.split(user).join(USER_PLACEHOLDER);
}
```

同时把 `07-logs.txt` 的标题从 `relative(input.homeDir, file)` 改为"homeDir 为空时用 `basename(file)`"，避免 `relative('')` 退化成整条绝对路径。

**测试**：`tests/core/diagnostics.test.ts`
- `homeDir 为空时不得破坏正文`：断言输出 **逐字节等于输入**；
- `homeDir 只有 1-2 个字符时同样跳过`；
- 4 种路径写法都能替换；
- JSON 二次转义能替换。

**验证**：`sanitize('hello world','')` → `hello world`（每字符不再被插入占位符）。

## D2 QQ ID 与 appId 覆盖

**根因**：旧规则 `\b\d{9,}\b` 只认 9 位以上数字，QQ 号常见 5–8 位；旧 appId 规则写了 `appId|appid|AppID` 但漏掉 `app_id`。

**修复**（`report.ts`）

```ts
out = out.replace(/\b(app[_-]?id)\b\s*[:=]\s*["']?\d{4,}["']?/gi, `$1=${REDACTED}`);
out = out.replace(
  /\b(qq|uin|openid|unionid|group[_-]?id|group[_-]?code|guild[_-]?id|channel[_-]?id|user[_-]?id|member[_-]?openid)\b\s*[:：=]?\s*["']?([0-9A-Za-z_-]{4,})/gi,
  `$1=${REDACTED}`,
);
out = out.replace(/\b\d{9,}\b/g, '<digits>');
```

**测试**：`appId: 1234567890`、`app_id=1234567`、`qq=12345`、`QQ 12345678`、`uin: 123456789`、`user_id: 987654` 全部断言"值不出现"；反向断言 `HTTP 200`、`port=51270`、`1234ms` 等诊断信息**不被误伤**。

## D3 凭据形状覆盖（日志与诊断双通道）

**根因**：`redact()` 只匹配 `sk-…`、`appSecret…`、`QQBOT_SECRET=…` 三种形状。实测以下全部原样输出：`DEEPSEEK_API_KEY=…`、`api_key: …`、`apiKey=…`、`token=…`、`password=…`、`Authorization: Bearer …`、`openid=…`。

**修复**（`logger.ts`）：改为"字段名驱动 + 已知值形状"两条腿，`sanitize()` 复用同一套规则：

| 规则 | 覆盖 |
|---|---|
| `sk-[A-Za-z0-9_-]{8,}` | DeepSeek / OpenAI 风格密钥 |
| `(Bearer|Basic|Token)\s+<credential>` | 保留认证方案名，丢掉凭据 |
| `(<名称>)(\s*[:=]\s*)(<值>)` | `DEEPSEEK_API_KEY=`、`QQBOT_SECRET=`、`api_key:`、`apiKey=`、`token=`、`password=`、`authorization:` … |
| `"<名称>": <值>` | JSON 段（`04-plugins.json` / `05-task.json`） |

`<名称>` 用 `(?<![A-Za-z0-9])(?:[A-Za-z0-9]*[_-])?(?:api[_-]?key|apikey|app[_-]?secret|appsecret|key|secret|access[_-]?token|…|authorization)s?(?![A-Za-z0-9])`：
既能让 `QQBOT_SECRET` / `deepseek_api_key` 命中，又**不会**把 `monkey=`、`hotkey=`、`keyboard:` 当成凭据（有专门用例守住这条）。

**测试**：13 条"值不出现"用例 + 1 条"普通文本逐字节不变"用例；`tests/adapters/policy.test.ts` 原有脱敏用例继续通过。

**验证**：打包应用真导出的 7 段，逐段扫描 `用户名/sk-/密钥字段` 均为 False（[m21-packaged-ui-diagnostics.log](./evidence/m21-packaged-ui-diagnostics.log)）。

## D4 预览与最终 ZIP 一致性

**根因**：`preview()` 与 `export()` 各自调用 `sections()` 重新采集。用户在预览后停留几十秒，日志会追加新行、网络探测结果会变化 —— ZIP 里可能出现**预览从未展示过的内容**（也就可能出现预览时被拦截、导出时才存在的凭据行）。

**修复**（`diag-service.ts`）

```ts
private previewed?: DiagnosticSection[];

async preview() { const sections = await this.sections(); this.previewed = sections; … }
async export()  { const sections = this.previewed ?? (await this.sections()); this.previewed = undefined; … }
```

同时把网络探测做成可注入（`networkProbe?`），使"预览与导出是同一份快照"可被测试证明。

**测试**：`tests/desktop/diag-service.test.ts`（3 例）
- 探针每次调用返回不同时间戳：断言 ZIP 含 `probe-1`、**不含** `probe-2`；
- ZIP 不含 `sk-profileOnlySecret999`（profile 内容）与 `QQBOT_SECRET` 值；但含 `config.json`（目录名允许）；
- 未预览直接导出时仍能自采集（7 段）。

**实机验证**：预览 `179/146/87/2/31/351/208` → 解压 ZIP 逐项字节数完全一致。

## D5 Harness 启动 30 s 误判失败

**现象**：全新部署后第一次"启动 Harness"必然失败，报 `等待 dsh web 启动超时（30s）`，且**子进程 30 s 内零输出**。重试一次即成功（3 s 就绪）。

**复现**：本轮 2 次独立失败（[run1](./evidence/m21-cold-start-failure-run1.log)/[run2](./evidence/m21-cold-start-failure-run2.log)）+ 1 次插桩复现（`PLAN 3568ms` → `FAILED after 30018ms`，无任何 OUT/ERR chunk）。根因指向"全新部署后的首次启动耗时显著超过 30 s（首启初始化 + 新写入的数百 MB 文件首次扫描）"，而不是协议解析问题。

**修复**（`packages/adapters/src/harness/cli.ts`）

```ts
export const WEB_START_TIMEOUT_MS = 120_000;           // 首启可能远超 30 s
async launchWeb(profile, port, timeoutMs = WEB_START_TIMEOUT_MS) { … }
// 超时不再沉默：带上子进程尾部输出，便于用户/诊断定位
const tail = buffer.trim().slice(-400) || '（无输出）';
reject(new Error(`等待 dsh web 启动超时（${Math.round(timeoutMs/1000)}s）：${tail}`));
```

**验证**：在**刚部署完、从未启动过**的根目录上重跑集成测试 → `health=usable http=401`，整轮 **42.8 s**（其中幂等重跑 3.5 s，首次启动约 39 s）——正好落在旧的 30 s 阈值之外，证明旧阈值必然误判。

## D6 取消清理会删除用户 Harness profile（P0）

**缺陷代码**（`deploy-plan.ts`，`ensure-profile` 步骤）

```ts
ctx.created(join(paths.dshHome, 'profiles'));   // ← 把用户数据目录写进"本任务创建的路径"
```

**影响链**：`created[]` 是"取消 + 清理"与"回滚"的删除白名单（`rollbackPlan()` 直接 `rm(path, {recursive:true, force:true})`）。一旦用户在 `install-qqbot` / `verify-plugin` 阶段取消并勾选清理，`dsh-home\profiles` 会被**递归删除** —— 里面是用户的 Harness profile（配置、插件数据）。

M2 的 S5 之所以看起来"用户数据完好"，是因为那次取消发生在 `install-dsh` 阶段，`created[]` 里还没有这条路径。

**修复**

```ts
// dsh-home 属于用户：即使本步骤创建了它，也不是安装产物。
// 记入 created[] 会让"取消 + 清理"删掉用户 profile（config、插件、凭据），产品绝不能这么做。
await getCli().ensureProfile(BASELINE.dsh.profile);
```

同时给 `buildDeploySteps` 增加可选 `cli` 注入，使该规则可被单测固定。

**测试**：`tests/desktop/deploy-plan-cleanup.test.ts`（3 例）
1. `ensure-profile` 执行后 `created[]` **必须为空**，且任何记录都不得落在 `dshHome` 之内；
2. 取消清理场景：`dsh-home/profiles/web/config.json` 内容完好，只有安装产物被删，`status` 变 `rolled-back`；
3. 抽查 5 个安装步骤的产物前缀都不在 `dshHome` 下。

**有效性验证**：把旧代码临时还原后，用例 1 **失败**（`expect(created).toEqual([])` 命中 `dsh-home\profiles`）；恢复修复后通过。

## D7 `FileVersion = 33.4.11`

**根因**（完整推理见 [审计报告 §5](./M2.1-独立审计报告.md)）：`signAndEditExecutable: false` 同时关闭了"写版本资源"；打开它则 electron-builder 25.1.8 会先解析 `winCodeSign` 工具链，而该 7z 内含 macOS 符号链接，**非管理员无法解压**，构建直接失败（本轮实测 `Cannot create symbolic link … libcrypto.dylib`）。即：在非管理员机器上，electron-builder 把"版本资源"和"签名工具链"绑死。

**修复**：两段式构建 + 纯 JS 版本资源写入。

| 文件 | 变更 |
|---|---|
| `package.json` | `dist` = `electron-vite build && electron-builder --win --dir --x64 && node scripts/set-win-version.mjs && electron-builder --win nsis --x64 --prepackaged release/win-unpacked`；新增 `copyright` 字段；新增 devDependency `resedit@1.7.2`（MIT） |
| `electron-builder.yml` | 保持 `signAndEditExecutable: false`（不碰 winCodeSign），并加注释说明为何由脚本写版本资源 |
| `scripts/set-win-version.mjs`（新增） | 用 `resedit` 读 PE → 改 `VersionInfo`（`FileVersion=0.2.0`、`ProductVersion=0.2.0.0`、`FileDescription/ProductName/InternalName/OriginalFilename/LegalCopyright`）→ 写回 |

**为什么不引入签名**：`K-M2-05`（无证书）未解除；本次目标只是让版本信息正确，不改变签名状态。

**验证**：`release\win-unpacked\DeepSeek Deploy Assistant.exe` → `FileVersion 0.2.0 / ProductVersion 0.2.0.0`；安装后 `%LOCALAPPDATA%\Programs\DeepSeek Deploy Assistant\DeepSeek Deploy Assistant.exe` 相同；安装包自身 `FileVersion 0.2.0 / ProductVersion 0.2.0`；界面页头 `M2 原型 · 0.2.0`。

## D8 卸载残留空程序目录

**根因**：electron-builder 的卸载段以 `RMDir /r $INSTDIR` 结束，内容清空后 `$INSTDIR` 本身因"是卸载器自己的工作目录"被 Windows 持有，删除失败 → 留下空目录。

**修复**（`build/installer.nsh`，通过 `nsis.include` 挂到 `customUnInstall`）

```nsis
!macro customUnInstall
  SetOutPath $TEMP                       ; 先离开该目录
  RMDir "$INSTDIR"                       ; 重试一次
  ${If} ${FileExists} "$INSTDIR"
    ; 仍被占用：退出后用独立进程回收；rmdir 不带 /s，只能删空目录
    FileOpen $0 "$PLUGINSDIR\rmdir.bat" w
    FileWrite $0 "@echo off$\r$\n"
    FileWrite $0 "cd /d $\"$TEMP$\"$\r$\n"
    FileWrite $0 "ping -n 3 127.0.0.1 >NUL$\r$\n"
    FileWrite $0 "rmdir $\"$INSTDIR$\"$\r$\n"
    FileWrite $0 "del $\"%~f0$\"$\r$\n"
    FileClose $0
    nsExec::Exec '"$SYSDIR\cmd.exe" /C "$PLUGINSDIR\rmdir.bat"'
  ${EndIf}
!macroend
```

**安全性质**：延迟回收使用**不带 `/s` `/f` 的 `rmdir`**，只有目录为空才会成功 —— 用户往安装目录里放的文件绝不会被删。

**验证**：静默安装 → 静默卸载：`installDir exists=False`；交互安装 → 交互卸载：`installDir exists=False`，注册表 0 条，两个快捷方式均删除，用户数据 + sentinel 保留（[m21-install-uninstall.log](./evidence/m21-install-uninstall.log)）。
