## D01 · 索引构建链

| 项 | 内容 |
|---|---|
| **原始任务要求（原文）** | `scripts/build-index.ts` + overlay + CI 校验，**校验直接调用 `parseMarketIndex`**；说明每个字段由官方库负责 |
| **原始验收标准（原文）** | 产出通过官方校验器的 `index.json`（含 `publishTimestamp`、`engines.dsh`、相对图标路径）；缺字段/坏图标（>32 KiB）即 CI 失败 |
| **前置条件** | P-3（引入 `@deepseek-ai/dsh-plugin-market-index@0.2.1-alpha.4`，作为**构建期 devDependency**，不进运行期）；P-7 已完成 |
| **技术实现方式** | ① `catalog/entries/*.ts` 为唯一事实来源 → `build-index.ts` 生成 `index.json`（官方 format 1）。② 生成后**必须**调用 `parseMarketIndex(json, indexUrl)`，捕获 `MarketIndexError` 并打印 `error.path` + `error.reason`（本次实测格式：`$.plugins[0].versions[0].publishTimestamp must be an integer …`）。③ 追加我方断言（官方不检查的部分）：`publishTimestamp` 与 registry `time[version]` 一致、`name/version` 与包实际一致、包声明了 `dsh.bundle.patch`、图标 decoded ≤32 KiB、`engines.dsh` 命中 `compat.json` 的 `verified-local` 条目、`source.npm.integrity` 与 registry 一致。④ overlay 字段（license/integrity/depsClosure/acceptance/safety）**不写入 `index.json`**，单独产出 `catalog.overlay.json` 并在构建期用 zod 校验。⑤ CI 步骤：`npm run build:index && npm run validate:index`，任一失败 exit 1 |
| **依赖关系** | 依赖 P-3、P-7；被 D02（数据源）、D09（内容）、D10（未来消费）依赖 |
| **测试标准** | ① 合法索引通过；② 删除 `publishTimestamp` → 失败且错误路径为 `$.plugins[0].versions[0].publishTimestamp`；③ `version='latest'` → 失败；④ 图标 32769 B → 失败；⑤ 纯中文 `title` → 失败（`must contain en`）；⑥ overlay 缺 `license` → 失败；⑦ 生成物与 `parseMarketIndex` 返回值逐字段一致（防止"生成了但没校验"） |
| **验收标准** | CI 上 `index.json` 通过官方校验器；四类坏输入均导致 CI 失败；构建日志打印"每个字段由官方库负责"的映射表（作为代码注释或生成文档） |
| **风险** | ① 把 overlay 字段塞进 `index.json` → 被**静默丢弃**（本次已实测），造成"看起来生效"的假象 → 用测试 ⑦ 兜底；② 官方校验器升级导致格式漂移 → 锁定 `0.2.1-alpha.4` 精确版本，升级需重新跑本任务的全部用例 |
| **可并行** | ✅ 与 D11 并行 |

## D04 · 本地导入

| 项 | 内容 |
|---|---|
| **原始任务要求（原文）** | zip / tgz / 目录 三种导入，统一转为 `file:` 规格 |
| **原始验收标准（原文）** | 三种格式均安装成功；非法包给出可读错误；目录导入先打包 `.tgz` 再交给 pnpm |
| **前置条件** | D03；`zip-writer` 扩展（需支持 tar/gzip，若无则引入 `tar` 依赖）；**许可门禁必须先行**（导入内容不得含 `UNLICENSED`） |
| **技术实现方式** | ① 三种输入统一入口 → 产出**绝对路径** `.tgz`（`parseInstallSpec` 实测要求绝对路径，相对路径会被拒："a local path must be absolute"）。② 导入前计算 SHA-256 并与 catalog 比对，不一致即拒（这是"清单哈希参与安装"的唯一位置）。③ 校验包内容：`package.json` 存在、`name/version` 与 catalog 一致、声明了 `dsh.bundle.patch`、无 `install/postinstall` 脚本（或要求显式授权 → `allowBuilds`）。④ 解压前做 zip-slip 防护（现有 `extract.ts` 已有，需复核覆盖 tar）。 |
| **依赖关系** | D03、D11 |
| **测试标准** | ① zip/tgz/目录各一次成功；② 缺 `package.json` → 可读错误；③ 版本与 catalog 不一致 → 拒绝；④ 路径穿越 zip → 拒绝；⑤ SHA-256 不匹配 → 拒绝且不留文件（复用 P-9 修正后的错误码） |
| **验收标准** | 三种格式均落地并出现在 `dsh plugin list`；非法包零残留 |
| **风险** | ① 目录打包遗漏 `files` 白名单 → 包不可用；② 打包后 `integrity` 与 registry 不一致 → 只能用于"用户自备包"，不得混入 catalog 的 `integrity` 断言 |
| **可并行** | ✅ 与 D06 并行 |

| **依赖关系** | D01、P-2、P-8 |
| **测试标准** | ① mock registry 第一源 500 → 自动换第二源成功；② 第一源返回被篡改 tarball（integrity 不符）→ pnpm 拒绝 → 归因 `registry` → 换源；③ 私有源请求不落到公共源（`registryPlan` 单测已覆盖，需在本产品补同款单测）；④ `registryPlan` 输入/输出快照测试（防上游行为变化） |
| **验收标准** | ① 镜像失效自动回退有日志可证；② **无 VPN 安装成功已实测（2026-11-04 直连复测：37/37，镜像比官方源快约 19 倍）**，但 D06 仍需补：**tarball 实际 host 记录** + **干净机器复测** + **失效代理检测**（P-11） |
| **风险** | ① 本次直连复测中仍观察到部分 tarball 从官方源下载（1–43 KiB/s），成因未完全确认 → 用"记录实际 host"兜底，禁止对用户承诺"全部国内下载"；② 上游 `registryPlan` 规则变化（experimental 包）→ 用快照测试锁定；③ 遗留 `HTTP(S)_PROXY` 会使安装退化到 70 s 级 |
| **可并行** | ✅ 与 D04 并行 |

## 2. 完成定义（DoD）

一个 M4 任务视为完成，必须同时满足：

1. 代码已提交到分支并可通过 `npm run typecheck`；
2. 新增/修改的行为有对应单测或组件测试，且全量 Vitest 无新增失败；
3. 对应的 **Gate 4 条目** 或 **PRD §10 条目** 有可复现证据（命令 + 输出 + 文件路径）；
4. 若结论是"不可行/未验证"，**必须有书面记录**（不得静默跳过）；
5. 审计矩阵只按"代码 + 测试证据"更新，不按"UI 已完成"更新。
