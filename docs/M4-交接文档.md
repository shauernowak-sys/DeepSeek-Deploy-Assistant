## 5. 操作规程与踩过的坑（**这部分最省时间**）

### 5.1 Windows / PowerShell

1. **执行策略禁止 `npm.ps1`**：一律 `cmd /c "npm.cmd run <script>"`。
2. `cmd /c "... 2>&1 | Out-String"` 会把 stderr 变成 `NativeCommandError`（exit 1），**判读要看日志/`$LASTEXITCODE`**，不要看 PowerShell 的红色输出。
3. **不要用 PowerShell here-string / `Set-Content` 写中文**：会乱码（已发生两次）。中文文件一律用编辑工具写。
4. `Set-Content -Encoding UTF8` 在 PS 5.1 会写 **BOM** → `JSON.parse` 直接失败（`Journal.load` 返回 undefined，界面显示"没有任务"）。写 fixture JSON 用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`。

### 5.2 pnpm / dsh

1. `pnpm pack --ignore-scripts` **无效**，必须 `--config.ignore-scripts=true`。
2. `npm_config_store_dir` **对 pnpm 无效**（本机真实 store 是 `D:\.pnpm-store\v11`），只有 `--store-dir` 或 `.npmrc` 生效。
3. **profile 恢复后必须 `pnpm install --offline --frozen-lockfile --force`**：普通 install 会被判 `Already up to date`，插件根本没链接回来。该参数固化在 `PROFILE_REBUILD_ARGS`。
4. `dsh plugin add` 自身**没有 registry 回退**；`--registry=` 会先被用于 `pnpm view` 预检。
5. 宿主 `0.2.0-rc.2`：**没有** index 读取方、`plugin_manager` 工具默认禁用、不支持 in-place upgrade（升级 = remove + add）。
6. `pnpm licenses list` 在**自定义 store** 下会报 `ERR_PNPM_MISSING_PACKAGE_INDEX_FILE`；审计候选时改为遍历已安装 `node_modules`（见 `scripts/candidate-audit.ts`）。
7. `dsh.bundle.patch` **可能是字符串也可能是数组**（`@8kugames/dsh-zed-acp` 是数组）。判断"是不是 bundle"要按 `string | string[]` 两种都算，否则会误判成非插件。
8. 候选审计一律 `--ignore-scripts` + 独立 store：**不要**为了"看看能不能装"去执行第三方安装脚本。

### 5.3 许可与分发边界（硬红线）

1. `@tencent-connect/qqbot-connector@1.2.0` 是 **UNLICENSED** → QQ 插件**只能在线安装**，离线包/镜像/重打包/本地导入全部会被 `assertRedistributable()` 拦下。
2. `needs-review` 许可**默认阻断分发**，不要为提高通过率放宽。
3. **改了 `package.json` 依赖 → 必须重跑 `licenses:build` + `notices:build`**，否则 CI 的 `licenses:check`/`notices:check` 会红。
4. 生成的 `THIRD_PARTY_NOTICES.md`、`licenses/**` 由 `.gitattributes` 固定 LF；比对时脚本会归一化 CRLF。

### 5.4 Electron UI 自动化（本项目做法）

1. 启动：`npx electron . --remote-debugging-port=93xx`，用 CDP（WebSocket）操作，**不要**引入 Playwright 依赖。
2. 键盘走查必须 `Emulation.setFocusEmulationEnabled` + `Page.bringToFront`，否则窗口没焦点时 Tab 不推进。
3. 只有 `--force-device-scale-factor=1|1.25|1.5` 才是**真实 DPI**；`element.focus()` 不会触发 `:focus-visible`，焦点环检查会失真。
4. 隔离数据目录：启动时把 `LOCALAPPDATA` 指到临时目录，脚本里再预置 `state/backups`、`state/tasks`、`runtimes/pnpm/.../pnpm.cjs` 三个 fixture，界面才有真实内容可查。

### 10.3 必须实现的呈现契约（来自 [D09 报告 §1](./M4-D09-完整策展-实施报告.md)）

1. **候选不得有安装按钮**：`status !== 'verified'` 一律不渲染安装入口（组件测试要覆盖）。
2. **候选分区独立**：`已验证` / `待评估(needs-review)` / `不可用(blocked)` 三个区；后两个区必须展示 `review.blockers[].code` 的中文解释 + `detail`。
3. **"装上了 ≠ 可用"**：`dsh-plugin-catalog` 就是反例——它能被 `plugin add` 装上并出现在 `plugin list`，但不是 bundle。UI 必须把"已安装"和"已加载"分开显示（PRD §10.4）。
4. **失败态不得空白**：索引解析失败要显示错误与下一步（CN-7）。
5. **风险必须展示**：`safety.network` / `safety.permissions`（例如 QQ 插件加载即向 `q.qq.com` 发起绑定）。

### 10.4 禁止事项

1. 不要放宽"`verified` 才能安装"的判定来让界面好看；
2. 不要把候选写进 `index.json`（`buildMarketIndex()` 已只取可安装条目）；
3. 不要修改 `packages/spec/src/domain.ts` 的 `BASELINE`；
4. 不要因为有 UI 了就把验收矩阵里 PLG-1/PLG-2/A7 改成"已完成"——**底层证据齐了才改**，且要附截图与测试；
5. 不要用 Playwright 等新依赖做 UI 自动化，沿用 `scripts/m4-*-ui-smoke.mjs` 的 CDP 做法。
