## 文档时效与冲突

`docs/audit/V0.1-完整功能验收矩阵.md` 的部分旧行仍写系统 Node 完全未检测、永远安装官方 QQ 插件、资源中心无入口；当前 `packages/adapters/src/detect/system.ts`、`packages/core/src/decide/installation.ts`、`apps/desktop/src/main/services/deploy-plan.ts` 和 D02 代码已经改变这些事实。本次真实 Node 复用探测通过，但并不代表全部边界场景验收完成。矩阵中较早的验收清单亦未全面同步多路线门禁更新，实测结论应以当前代码与实际证据为准。

## 建议的测试顺序

1. 固定当前待测代码及其标识，构建新的候选安装包，记录版本和哈希；在隔离环境检查启动、内置资源、许可文件、安装卸载及数据保留。
2. 开发人员陪同，用可还原的 Win10/Win11 普通用户环境分别走官方 QQ 与个人 QQ 路线；先测试环境检测、部署、API 和故障恢复，再进行真实账户接入。测试者使用独立账户，自行输入密钥与完成授权，不在报告中记录凭据或隐私内容。
3. 按用户门禁清单逐项记录真实 QQ 场景、时间、系统、应用版本和脱敏证据；同时验证不同现有环境与网络情况。遇到密钥明文或意外删除等问题停止对应场景并修复。
4. 修复测试中的阻断项并重新生成候选包；之后再组织 A14 三人独立测试。只有各项发布门禁及适用的书面决策完成后，才能判断是否达到 V0.1 发布条件。
