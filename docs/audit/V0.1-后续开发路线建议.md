# V0.1 后续开发路线建议

**性质：** 建议稿。**不改变既定阶段编号（M0–M5）**，不新增阶段，不把 V0.1 需求推迟到 V0.2。
**依据：** [03-开发任务拆分](../03-开发任务拆分.md)（阶段与任务 ID）、[PRD-V0.1-FROZEN](../PRD-V0.1-FROZEN.md) §18.3/§20、本次[审计矩阵](./V0.1-完整功能验收矩阵.md)。

---

## 0. 先明确三个前提

1. **M4 不是 V0.2 的功能，而是 V0.1 的 P0 需求。** PRD §20.2 明确要求 V0.1 最低实现包含"§10 资源库（核心清单 + 元信息字段 + 哈希校验 + 三层下载 + 许可判定）"，§18.1 的 A7/A8/A9 也直接依赖它。`docs/03` 里"M4 可与 M3 后半段并行"的表述容易被读成"可延后"，实际应理解为"可与 M5 前半段并行"。
2. **M3 尚未关闭。** M3 的原任务 C01–C07 中，C02（Desktop 分支）、C06（真机验收）、C07（Desktop 引导与只读快照）仍未完成。
3. **门禁不由开发推进。** QQ-GATE-01/02 的通过数量只随用户证据变化，任何开发批次都不得改动计数。

## 8. 不建议做的事（防止走偏）

1. 不建议为了提高"完成率"把 64 项"部分完成"直接标成"已完成"——其中 31 项是 P1。
2. 不建议在 M4 之前先做 V0.2 的任何增强（§20.4 的部署引擎升级、诊断规则引擎、资源库富文本等）。
3. 不建议把 `SnowLuma` 自动部署的"blocked"去掉以让流程"看起来顺畅"——那是 EULA §5.4 的硬约束。
4. 不建议用 Mock 或本地回环验证 QQ 链路（QG-3 明确禁止）。
5. 不建议在 Win11 干净机、三人测试、五态检测未完成前对外宣称"支持 Windows 10/11、零基础可用"。
