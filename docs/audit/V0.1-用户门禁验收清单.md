# V0.1 用户门禁验收清单

**性质：** 本清单只**定义**需要用户本人执行的真实环境验收，**不代为执行、不代为判定、不修改任何通过数量**。
**当前计数（本次审计未改动）：** QQ-GATE-01 = **2/6**；QQ-GATE-02 = **0/12**。
**事实源：** 代码侧门禁常量在 `packages/spec/src/gates.ts`（单一来源），证据在 `docs/evidence/`。
**规则（摘自 PRD §18.2，不可协商）**

| # | 规则 |
|---|---|
| QG-1 | 门禁未通过时，允许内部研发与安装器测试（含向测试用户分发） |
| QG-2 | 门禁未通过时，**不允许**在任何对外文案/商店页/演示中宣称"官方 QQ 已完整可用/已支持收发" |
| QG-3 | **不允许**用 Mock、假机器人、回环消息、截图伪造替代真实收发验收 |
| QG-4 | 仅当产品负责人 + 技术负责人共同签署"该版本不对外宣称 QQ 能力"的降级发布决议，方可发布不含 QQ 宣称的版本 |
| QG-5 | 门禁结论必须附证据（日志/截图/时间/环境），**无证据视为未通过** |

**证据记录规范**

- 存放：`docs/evidence/`（建议 `qq-gate01-<序号>-<日期>.{log,md,png}`）
- 每条至少包含：时间与时区、机器（OS 版本）、应用版本（0.2.0）、插件版本（`@tencent-connect/dsh-qqbot@0.5.5`）、脱敏截图或日志片段
- **不得**包含：AppSecret、OneBot accessToken、完整 API Key、QQ 消息正文中的人名/手机号
- 本清单不要求现在执行，也不构成开发任务。

## 四、记录与回写规则

1. 用户完成一项 → 在 `docs/evidence/` 新增证据文件（命名见上方规范）。
2. `packages/spec/src/gates.ts` 的 `QQ_GATE_01/02` 计数**只在证据文件存在后**由后续开发更新；本次审计**未做任何修改**。
3. 若某项实测"上游不支持"（如插件只支持一种绑定方式），必须在 PRD 与 UI 同步标注，并登记为 `not-supported`，**不得**记为通过。
4. 本清单**不得**被当作开发任务分派给 Codex；它仅描述"用户要做什么、交什么证据、达到什么标准"。
