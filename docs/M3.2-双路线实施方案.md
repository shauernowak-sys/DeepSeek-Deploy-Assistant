## 1. 目标与非目标

### 1.1 目标

1. 用户在桌面软件里**先选路线**（官方 QQ Bot / 个人 QQ），再用各自的流程完成接入。
2. 两条路线的**配置、状态、卸载、数据完全隔离**。
3. 个人 QQ 走**成熟的第三方组件**，我们**不实现 QQ 协议**、**不打包/不镜像**第三方组件。
4. 所有"已连接/可用"的结论都必须有**运行时证据**（禁止"配置文件存在 = 已连接"）。
5. 报告口径固定为六类：**已实现 / 自动化测试通过 / 真实环境测试通过 / 待人工验收 / 不支持 / 受许可证限制**。

### 1.2 非目标（本轮明确不做）

- 不做 QQ 协议逆向、不做代登录、不做风控绕过。
- 不打包 NapCat / Lagrange / LLBot 二进制，不提供第三方组件的国内镜像。
- 不做第三方组件的**自动更新**（PRD §19-9）。
- ~~不引入 SnowLuma（任务书明令排除）。~~ → **路线调整（PRD R4，2026-11-03）：个人 QQ 采用 SnowLuma**；NapCat/Lagrange 不再作为候选。个人 QQ 的实施细节见 [SnowLuma 专项技术调查报告](./M3.2-SnowLuma专项技术调查报告.md) 与 [SnowLuma 实施计划](./M3.2-SnowLuma实施计划.md)。
- 不做 Harness 本体开发，不改 Harness 源码。

## 3. 阶段 B：技术选型计划（先调查、后动手）

### 3.1 评估矩阵与打分规则

每个候选按 10 个维度打 1–5 分，**加权后排序**；任一"一票否决项"命中即不进入推荐位。

| 维度 | 权重 | 打分依据 |
|---|---|---|
| 活跃度与维护 | 15% | 最近提交/发行时间、issue 响应、是否归档 |
| 许可证（商用） | **一票否决** | LICENSE 原文是否允许商业使用 |
| 再分发权利 | **一票否决** | 是否允许我们随安装包分发/镜像 |
| 依赖项许可证 | 10% | 依赖闭包逐项判定（对齐 §10.3 CN-5） |
| Windows 可运行性 | 15% | 是否有官方 Windows 发行包；是否需要额外运行时 |
| 安装难度（普通用户） | 15% | 是否需要命令行、是否需装 QQNT/LiteLoader |
| Harness 适配成熟度 | 20% | 是否有成熟适配插件；适配插件的 dsh 兼容区间 |
| 消息能力 | 10% | 私聊、群聊、图片的真实支持 |
| 稳定性（断线/重启恢复） | 10% | 断线重连、重启免登录、崩溃恢复 |
| 凭据存储安全性 | 5% | 登录凭据存放位置与是否加密（**只记录事实，不假定**） |

**一票否决的记法**（对齐 PRD §12.1）：`可自动安装` / `可引导安装` / `不可用` 三选一，不给"部分可用"。

### 3.2 实验清单（全部在 `%TEMP%` 副本上，不动真实实例）

| 实验 | 输入 | 产出 | 结论用途 |
|---|---|---|---|
| **B-X1 ✅** | 副本 `DSH_HOME` + dsh `0.2.0-rc.2` + `dsh-qq-link@1.5.1` | **通过**：可安装、可加载、与官方插件共存、`/dsh-qq-bridge/state` 可读 | 定案：采用 `dsh-qq-link`（E-C） |

| **B-X3 ⛔** | 读 `@deepseek-ai/dsh-agent` 的 `agents` 服务类型 | 取消 | 成熟插件可用，不自研 |
| **B-X4 ⏳** | 用户手动安装 NapCat | 真实进程名、WebUI 端口、OneBot HTTP 端口、`get_login_info` 返回 | 装后检测的**真实**判据（PRD U15） |

**纪律**：B-X1/B-X2 只用副本；B-X4 需要用户手动安装，我方只做只读探测；任何实验产物都不进 `release/`，不提交。

| 双路线共存 | 两条路线的凭据/配置/状态同存；官方 `secrets.bin` 与个人 `state/personal-qq.json` 互不覆盖 |
| 路线切换 | 切换只改首屏偏好，不改任何一条路线的运行状态 |
| 分别启动/停止 | 官方 Harness 停止不影响个人组件的运行状态显示（反之亦然） |
| 一条路线异常 | 个人 QQ 组件崩溃 → 官方路线状态与 API 配置**保持正常**（回归断言） |
| 配置隔离 | 保存个人路线设置后 `llm-deepseek` / `agent-default-model` / `im-qqbot` 三块**逐字节不变** |
| 卸载隔离 | "重置个人 QQ"只删我们自己的 state，不删 `secrets.bin` 的 `qq.*`、不删组件目录 |

## 9. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 使用**未声明兼容**组合（`dsh-qq-link` 声明 0.2.1-rc.3，我们用 0.2.0-rc.2） | 插件边界能力（面板/语音/空间）可能失效 | 只依赖已实测的 HTTP 契约；插件升级前先跑一遍 B-X1 同款冒烟；兼容矩阵登记 `verified-local` 并写明"未声明组合" |
| 第三方组件被腾讯风控/封号 | 用户个人 QQ 不可用 | UI 明示"个人 QQ 接入属非官方途径，存在账号风险"，不承诺可用性；只做引导，不代操作 |
| Harness 插件 API 破坏性变更 | 自研适配层失效 | 锁定 `0.2.0-rc.2` 并在兼容矩阵登记；适配层不进入核心部署链，可单独卸载 |
| 装后检测误报"已连接" | 违反 PRD §10.4 | 四段式取证 + 每段证据行上屏；"已联通"必须有 Harness 侧证据 |
| 升级基线（E-B1）导致官方 QQ 回归 | P0 | 默认不选；若选则必须重跑 QQ-GATE-01 全部门禁 |
| 受管块改写破坏宿主配置（A-05） | 用户 UI 设置丢失 | 阶段 C 先修，再动个人 QQ |
| 个人路线的文件操作误删用户数据 | P0 | 只写自己的 `state/`；所有删除操作限"本软件创建"产物；测试用临时目录断言 |
