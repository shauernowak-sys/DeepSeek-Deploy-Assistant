## 1. 设计依据（已核实的事实基线）

所有约束来自对一手源码/文档的核对，出处见 [02-开源项目复用盘点](./02-开源项目复用盘点.md)。

| # | 事实 | 设计约束 |
|---|---|---|
| F1 | 公开分发形态是 npm 包 + `dsh` CLI（`npx @deepseek-ai/dsh web`），MIT | 不打包本体；**CLI 路线**下 Node.js 为硬前置（Desktop 路线由应用内置）；版本固定到具体 prerelease 串 |
| F2 | Harness 处于 developer preview，官方声明会有破坏性变更 | 必须"版本固定 + 三级兼容判定 + 升级/降级路径"（见 F10、§6.6） |
| F3 | `dsh plugin --profile <name> add <pkg>` 转发 pnpm | 插件安装/卸载全部经 CLI；离线包必须是 `.tgz` |
| F4 | `dsh-qqbot` 为腾讯官方插件（MIT），QQ Bot API v2，扫码绑定，`QQBOT_APPID`/`QQBOT_SECRET` 可注入 | 官方 QQ 模式不自建协议栈、不自建扫码 |
| F5 | Harness 插件索引 `format: 1`，支持 npm registry 覆盖与 git commit 固定 | 资源中心产出 DSH 兼容 `index.json` |
| F6 | Web UI 默认 `127.0.0.1:3080`，`--port 0` 可随机、`--no-open` 可抑制开窗；**实际启动需 token，无 token 一律 401**（F22） | 运行态探测基于端口 + HTTP 响应（**401 视为在线**） |
| F7 | NapCat 许可禁止商业使用、限制再分发 | 任何第三方网关都不得预置进安装包 |
| F8 | 仓库内已有官方桌面端（`apps/desktop`：Electron 壳 + NSIS per-user 安装器 + 自动更新 + 内置 pnpm）；GitHub Releases 仅有 prerelease 且无二进制资产 | 必须**先判定路线（CLI / Desktop）**；Desktop 路线不改装、不越权，只做引导与检测 |
| F9 | Desktop 拥有 `$DSH_HOME/profiles/desktop`，**CLI 无法启动该 profile，npm 安装的 dsh 也不能修改它** | `dsh plugin` 只对 CLI profile 有效；禁止把"用 CLI 给 Desktop 装插件"写成方案 |
| F10 | 插件包声明 `dsh.compatibility.dshReleases`（如 qqbot 0.5.5 = `0.1.0-rc.8` / `0.2.0-rc.2`），且可不声明 `engines.dsh`，改用 `@deepseek-ai/dsh*` peerDeps | 兼容判定三级顺序：`compatibility.dshReleases` → `engines.dsh` → peerDeps |
| F11 | npm `@deepseek-ai/dsh` 的 `latest` 指向 prerelease（`0.2.1-rc.5`），共 40 个版本，无 `engines.node` 声明 | 版本固定到具体 prerelease 串 + 记录通道；Node 下限按插件要求取 20.3.0 |
| F12 | 官方提供索引校验库 `@deepseek-ai/dsh-plugin-market-index`（MIT，零依赖，`parseMarketIndex` / `marketInstallTarget` / `MAX_INLINE_ICON_BYTES`） | 索引 schema 与安装规格**直接复用**，不自研、不复制规则 |
| F13 | `$DSH_HOME` 解析顺序：`dshHome` 配置 → 环境变量 `DSH_HOME` → `~/.dsh`（`packages/shell/shell-env`） | 所有路径探测必须走同一解析函数；禁止硬编码 `~/.dsh`，否则自定义 home 用户的 profile 会被漏检 |
| F14 | 共享插件管理器（`packages/boot/plugin-manager`）接受**任何 `pnpm add` 规格**（含 `file:` 绝对路径、`link:`、registry 标签/别名）；索引源通过 profile 设置 `indexes` 配置，只接受 `http(s):` URL | 离线安装用 `file:` 绝对路径即为官方支持的形态；我方索引可通过本地 HTTP 注册进 `indexes` |
| F15 | `dsh --profile <p> --from-default-profile <t>` **会替换整个目标目录**并删除原 `package.json`/`node_modules`/`cordis.patch.yml`（v0.2.1-alpha.2 升级指南明确写明） | `rescue` 只能作为"重置"手段，且执行前必须备份 profile；**不得**当作可逆回滚 |
| F16 | 内置 profile 名（`web`/`tui`/`desktop`/`headless`/`acp`/`sdk`/`sdk-minimal`，不区分大小写）在 0.2.x 中**不能作为 `--from-default-profile` 目标**；但 0.1.x 无该命令，且自定义名 profile 不含 Web UI（F20） | 0.2.x：自建 profile + 备份；0.1.x：以 `web` profile 为目标 |
| F17 | Desktop 安装包身份：`productName = "DeepSeek Harness"`、产物名 `deepseek-harness-<ver>-win-x64.exe`、`uninstallDisplayName = "DeepSeek Harness"`；`appId` 由环境变量注入、**不是稳定常量** | 检测只认 `uninstallDisplayName`/安装目录/`profiles/desktop` 等可观测信号，**不得**依赖 appId |
| F18 | Desktop 载荷约 **616,701,792 B / 11,735 个文件**；首次安装约 38 s（官方实测样本）；分发走腾讯云 COS + EdgeOne（`upload:*` 脚本） | 我方**不得**镜像/内置 Desktop 安装包；只做"打开官方入口 + 装后检测" |
| F19 | Desktop 升级/卸载"只改变安装文件，不改变外部 Desktop 插件 profile 或产品数据" | 卸载边界以此为准：卸载 Desktop 不等于删除 `profiles/desktop` |
| F20 | **0.1.x 无 `--from-default-profile`/`rescue`；自定义名 profile 只含 `dsh-base`（无 Web UI）。安装进 `--profile web` 才会带上 `dsh-web-app`**（M0-T3/T4 实测） | CLI 路线一律以 `web` profile 为目标；`dda-core` 专有名的设计作废 |
| F21 | profile 的 `pnpm-workspace.yaml` 为 `nodeLinker: hoisted` + **`autoInstallPeers: false`**；peer（`dsh-llm` 等）**不会**被安装 | 禁止用 `pnpm peers check` 的 warning 判定插件损坏；判定只看运行时证据 |
| F22 | `dsh web` 强制 token：无 token 的 `GET /`、`/healthz` 均返回 **401**；带 token 返回 303 | 运行态探测必须"**401 即在线**"，否则会误判未就绪 |

## 2. 运行形态

| 项 | 决策 |
|---|---|
| 支持的 Harness 路线 | V0.1 **只自动化 CLI 路线**；官方 Desktop 仅检测与引导（§6.6.3） |
| 我方 profile 名 | `web`（内置；0.1.x 下唯一能带 Web UI 的方式，F20） |
| profile 回滚 | 依赖我方 `profiles-backup\` 备份，不使用 `--from-default-profile`（F15，且 0.1.x 无此命令） |
| 进程模型 | 单实例应用（`requestSingleInstanceLock`），无托盘常驻（V0.1） |
| 安装位置 | per-user：`%LOCALAPPDATA%\Programs\DeepSeekDeployAssistant` |
| 权限 | **不请求管理员**。需提权的动作降级为"引导用户手动完成"并说明原因 |
| 网络 | 默认在线；核心组件必须能在"无 VPN、纯国内网络"下完成安装 |
| 离线 | 支持 `resources/offline/` 预置与用户自选目录 |
| 卸载 | 只删自己创建的文件；`runtimes/`、`plugins/offline/` 询问用户是否保留 |

## 3. 进程与信任边界

```
┌──────────────────────────────────────────────────────────────┐
│ Renderer (React + shadcn/ui)  sandbox=true, nodeIntegration=false
│  只持 DTO；永不见明文密钥；无文件系统权限                      │
└───────────────▲──────────────────────────┬───────────────────┘
                │ contextBridge（typed）    │ push events (task:event)
┌───────────────┴──────────────────────────▼───────────────────┐
│ Preload：window.dda.* 固定白名单 API（无 dynamic invoke）      │
└───────────────▲──────────────────────────┬───────────────────┘
                │ ipcMain.handle + zod 校验 │
┌───────────────┴──────────────────────────▼───────────────────┐
│ Main（Node.js 全权限）                                        │
│  ├ services/    装配层：把 core + adapters 组装成用例          │
│  ├ core         Plan/Step 引擎、journal、下载、校验、诊断      │
│  └ adapters     运行时 / 包管理器 / QQ 网关 / Harness CLI      │
└───────────────┬──────────────────────────────────────────────┘
                │ spawn（stdout/stderr 流式采集 + 脱敏）
┌───────────────▼──────────────────────────────────────────────┐
│ 外部子进程（全部在显式白名单内）                                │
│  dsh / pnpm / node / python / winget / 7za                    │
└──────────────────────────────────────────────────────────────┘
```

**长任务不阻塞主进程**：下载、解压、哈希放入 `utilityProcess`（Electron 的独立 Node 子进程），
主进程只保留编排与 IPC。进度事件按 100 ms 节流后推送渲染层。

## 4. 分层（对齐 PRD 7.2）

| PRD 层 | 代码位置 | 职责 | 禁止 |
|---|---|---|---|
| 桌面层 | `apps/desktop/src/renderer` | 向导、插件中心、配置引导、日志界面 | 直接访问 fs / child_process / 密钥 |
| 业务层 | `packages/core` | 检测编排、计划生成、任务状态机、下载、校验、诊断 | `import 'electron'`（须纯 Node） |
| 适配层 | `packages/adapters` | Node/Python/FFmpeg/Git 适配、包管理器、QQ 网关、Harness CLI、压缩包 | 含 UI 逻辑；硬编码具体网关品牌 |
| 契约层 | `packages/spec` | Manifest schema、IPC DTO、错误码、插件索引 schema（zod） | 含副作用 |
| 外部组件 | 进程外 | Harness、DeepSeek API、QQ 网关、第三方插件 | 把 Agent 运行逻辑放进本仓库 |


## 6. 领域模型

### 6.1 组件（Component）

一切"可安装物"都是 Component：

| 类别 | 例子 | 安装手段 |
|---|---|---|
| `runtime` | Node.js / Python / FFmpeg / Git | 下载 → 校验 → 解压或 silent 安装 → 子进程注入 PATH |
| `plugin` | `@tencent-connect/dsh-qqbot` | `dsh plugin --profile X add …` |
| `gateway` | 个人 QQ 协议端（V0.1 不交付） | 仅探测与引导 |

### 6.2 运行时清单（`manifests/runtimes/*.json`）

```jsonc
{
  "schemaVersion": 1,
  "id": "node",
  "version": "22.23.4",             // 固定版本，禁止 "latest"；24.22.2 为待实机验证的备选
  "arch": "x64",
  "source": {
    "url": "https://nodejs.org/dist/v22.23.4/node-v22.23.4-win-x64.zip",
    "mirrors": ["<国内镜像1>", "<国内镜像2>"],   // 按序回退，哈希仍以本字段为准
    "sha256": "cbc74b5e0982c9dbb41525fd8fb5dcd32fbee237863f7829072f4639a1ce5f20",
    "size": 35604229
  },
  "install": {
    "strategy": "portable-unzip",     // portable-unzip | silent-exe | embeddable-python
    "targetSubdir": "runtimes/node/22.23.4",
    "postSteps": []                   // 例如写入 .npmrc 镜像
  },
  "detect": {
    "minVersion": "20.3.0",           // 下限由 dsh-qqbot 的 engines.node 决定，不能只看 dsh 本体
    "acceptExisting": true,           // 已装兼容版本则复用（ENV-003）
    "probes": [
      { "kind": "path", "command": "node", "args": ["-v"] },
      { "kind": "registry", "key": "HKLM\\SOFTWARE\\Node.js" },
      { "kind": "file", "path": "%ProgramFiles%\\nodejs\\node.exe" }
    ]
  },
  "env": { "prependPath": ["."] },    // 仅对本应用 spawn 的子进程生效
  "license": { "spdx": "MIT", "textFile": "licenses/node-LICENSE.txt" }
}
```

要点：

- `acceptExisting: true` 直接落实 ENV-003"不重复安装已有的兼容环境"与 DEP-002"按需安装"。
- `env.prependPath` **只作用于我们 spawn 的子进程**，不写注册表、不改用户环境变量 → 卸载可完全回收。
- 清单本身须通过校验/验签后才被信任（§11.3）。

### 6.3 部署计划与步骤（Plan / Step）

```ts
interface Step {
  id: string;                     // 稳定 id，同时是幂等键（如 "node:download"）
  title: string;                  // 给用户看的一句话
  weight: number;                 // 进度权重
  destructive?: boolean;          // true 时二次确认
  precondition?(ctx: StepCtx): Promise<boolean>;   // true → 跳过（已是目标态）
  run(ctx: StepCtx): Promise<StepOutcome>;
  rollback?(ctx: StepCtx): Promise<void>;          // 仅撤销"本次新建"的东西
}

interface StepOutcome {
  evidence: Evidence[];           // 见 6.4
  next?: string[];                // 动态分支（如"需要重启"）
}
```

执行语义（`core/engine/executor.ts` 必须保证）：

1. 按拓扑序执行，`precondition` 为真即记 `skipped`（幂等，重跑安全）。
2. 每步开始/结束都写 journal（原子写：临时文件 + rename）。
3. 失败即 `paused` 并保留已完成步骤；用户点"继续"从第一个非 `succeeded` 步骤重入（DEP-003）。
4. `rollback` 只撤销**本次任务创建**的产物（journal 的 `created[]`），不动用户原有环境。
   profile 已被改坏时，优先恢复我方备份；官方重置命令（0.2.x 的 `dsh rescue --from-default-profile <p>`）**会删除目标目录**，仅在用户明确选择"重置"时使用（F15）。
5. 同一 `taskId` 串行（互斥锁）；跨任务并行度上限 2。

### 6.4 插件生命周期：五段证据模型

PRD 5.5 要求"必须区分"的五个状态，做成**累积证据**而非单一枚举：

```ts
interface PluginState {
  resolved:  Proof<{ name: string; version: string; source: 'npm'|'git'|'file'; integrity: string }>;
  downloaded:Proof<{ sha256: string; bytes: number; depsCached: number }>;
  installed: Proof<{ profile: string; exitCode: 0; listedAt: string }>;
  configured:Proof<{ requiredKeys: string[]; missingKeys: string[] }>;
  running:   Proof<{ checkedAt: string; probe: 'ws-heartbeat'|'http-ok'|'none' }>;
}

interface Proof<T> { ok: boolean; detail?: T; checkedAt: string; }
```

- UI 仅在 `installed && configured && running` 全绿时显示"可用"；否则显示"已下载/已安装，待配置/未连通"。
- `running` 的探测方式由组件声明（QQ 官方插件用 WS 心跳；Harness Web 用 HTTP 200）。**不允许用"进程还在"代替"可用"**。

### 6.5 任务状态机

```
        ┌────────┐  start   ┌─────────┐  all ok   ┌─────────┐
        │ pending├─────────►│ running ├──────────►│succeeded│
        └────────┘          └────┬────┘           └─────────┘
                                 │ step fail
                                 ▼
                            ┌────────┐  resume  ┌─────────┐
                            │ paused ├─────────►│ running │
                            └───┬────┘          └─────────┘
                                │ rollback
                                ▼
                          ┌─────────────┐
                          │ rolled-back │
                          └─────────────┘
```

`TaskRecord` 持久化于 `state/tasks/<taskId>.json`；`taskId` 由 `scenario + 目标版本集合` 派生，
因此**同一目标重复进入会命中已有任务**，天然实现"重复安装检测"（PLG-5）。

### 6.6 Harness 双路线模型（F8/F9/F13–F19）

#### 6.6.1 四态检测

`app:bootstrap` 必须把 Harness 状态判定为下列四态之一，且每种判定都要附**证据**（检测信号 + 原始值），不允许只给布尔值：

| 状态 | 判定信号（全部只读） |
|---|---|
| `cli` | `dsh` 可执行（PATH / 我方 `runtimes` / `npx` 缓存）；`<home>/profiles/<自定义名>` 存在；`dsh --help` 可解析出版本 |
| `desktop` | HKCU Uninstall 项 `DisplayName = "DeepSeek Harness"`（`uninstallDisplayName`，F17）或其 `InstallLocation` 下的主程序存在；`<home>/profiles/desktop` 存在 |
| `none` | 上述两者均无命中，且没有残留在测信号 |
| `multiple` | 两者同时命中（**最常见**：用户先用 CLI 后又装了官方桌面版） |

```ts
interface HarnessEvidence { signal: string; raw: string; ok: boolean; }
type HarnessRoute =
  | { kind: 'cli';      evidence: HarnessEvidence[]; home: string; version: string; profiles: ProfileInfo[] }
  | { kind: 'desktop';  evidence: HarnessEvidence[]; home: string; installDir?: string; version?: string }
  | { kind: 'none';     evidence: HarnessEvidence[] }
  | { kind: 'multiple'; evidence: HarnessEvidence[]; cli: CliInfo; desktop: DesktopInfo }
  | { kind: 'unknown';  evidence: HarnessEvidence[]; reason: string };   // 信号矛盾，禁止继续安装
```

- `home` 一律经 `resolveDshHome()` 计算（`dshHome` 配置 → `DSH_HOME` → `~/.dsh`，F13）。
- 任一信号相互矛盾（例如注册表有、目录无）时，**降级为 `unknown` 并展示"检测不完整"**，不得猜测为 `none` 后开始安装。

#### 6.6.2 路线决策与用户选择（不允许静默选择）

```
检测结果为 multiple
   ├─ 用户上次已选过路线（记住）→ 直接用上次选择，页面顶部显示"当前管理路线：CLI"
   └─ 未选过 → 强制选择页（默认高亮 CLI，并说明两者 profile 互不通用）
检测结果为 desktop
   ├─ 用户要做"插件/QQ 接入" → 只做引导：打开桌面端绑定页/插件管理，事后回读 `profiles/desktop` 状态
   └─ 用户要做"CLI 自动化部署" → 明确告知"将新建一套独立 CLI 环境，与桌面版互不影响"，二次确认后才继续
检测结果为 cli / none → 进入 CLI 标准自动化路线
```

**冲突处理（硬规则）**

1. `owner: 'desktop'` 的 profile 一律**只读**：`probe` 可读其存在与插件清单，`add/remove/spawn/set-config` 全部拒绝并给出引导文案（F9）。
2. 不允许把 CLI 的插件"映射"到 Desktop；也不允许把 Desktop 的凭据文件复制到 CLI profile（凭据归属各自 profile）。
3. 同一任务内不允许出现两条路线的步骤；用户中途切换路线 = 新任务。
4. 若 Desktop 正在运行，禁止启动会修改同一 `<home>` 的 CLI 任务（文件锁冲突），提示"请先退出桌面端"。

#### 6.6.3 双路线职责与归属（V0.1）

| 维度 | CLI 路线（V0.1 标准自动化） | Desktop 路线（V0.1 仅检测与引导） |
|---|---|---|
| 安装动作 | 支持：Node 运行时 → `dsh` 安装（官方渠道）→ profile 创建 | **不支持**：只提供官方入口（打开下载页/官网），不镜像、不代下、不静默安装（F18） |
| 版本管理 | 由我方清单固定（见 6.6.4），可升级/降级/回滚 | 由 Desktop 自带 updater 管理，我只读展示版本 |
| profile | `<home>/profiles/web`（**必须用内置 `web` 才能获得 Web UI**，见 F20） | `<home>/profiles/desktop`（只读） |
| 插件 | `dsh plugin --profile web add <spec>` 全流程 | 引导用户在其应用内插件管理操作；我只读结果 |
| 配置 | 我方写入 profile 配置（含提示词、QQ 插件配置） | 只读；引导用户在设置页修改 |
| 密钥 | 我方 DPAPI 保管 + 注入子进程环境变量 | 由其应用内存/绑定流程保管，我方不读不写 |
| 卸载 | 删除我方创建的文件；`profiles/web` 询问后删除 | 只提示"在系统设置中卸载"；不删除 `profiles/desktop`（F19） |

#### 6.6.4 版本兼容矩阵（唯一事实来源：`manifests/harness/compat.json`）

判定顺序（**不允许跳级**）：`plugin.dsh.compatibility.dshReleases` → `plugin.engines.dsh` → `plugin.peerDependencies` 中的 `@deepseek-ai/dsh*` 与宿主实际提供版本比对。

V0.1 只允许清单中标记为 `verified` 的组合；`unverified` 组合一律拒绝安装并说明原因，`blocked` 组合直接隐藏入口。

| 组合 ID | Harness | dsh-qqbot | Node | 依据 | V0.1 状态 |
|---|---|---|---|---|---|
| C1 | `0.1.0-rc.8`（CLI） | `0.5.5` | `>= 20.3.0` | 上游元数据声明 compatible（"CLI 已验证"） | **禁用**：M0-T3 实测 `dsh web` 启动即崩溃（`requires the Cordis HMR service`，3/3 复现，见 M0 报告 §4） |
| **C1′** | **`0.2.0-rc.2`（CLI）** | **`0.5.5`** | **`>= 20.3.0`** | 上游声明 compatible + **M0-T4 实测：pnpm 安装后 Web 启动成功、插件加载并进入扫码** | **允许（`verified-local`，待第二台机器/第二条网络复现）** |
| C2 | `0.2.0-rc.2`（Desktop 内嵌） | `0.5.5` | Desktop 自带 | 上游注明 Desktop 端内绑定页已验证 | 只读展示（Desktop 路线不装插件） |
| C3 | `0.2.1-rc.5`（npm `latest`） | `0.5.5` | — | **不在任何 compatible 列表** | 禁止（`unverified`） |
| C4 | `0.2.2-alpha.2`（npm `alpha`） | `0.5.5` | — | 不在兼容列表 | 禁止（`unverified`） |
| C5 | 任意 | `0.5.0` 及更早 | — | 无 `compatibility` 声明；`0.5.0` 仅 `engines.node >=18` | 禁止 |

> **M0 补充规则（重要）**：①上游"已验证"不等于本机可复现，矩阵条目必须带 `evidence`（本机日志路径或上游链接）；
> ②`profile` 的 `pnpm-workspace.yaml` 显式设置 `autoInstallPeers: false` → **peer 缺失属预期**，不得据此判插件损坏；
> ③安装必须用 **pnpm**（npm 在本机挂起 14 分钟无进展，见 M0 §3）。

推导链（供复核）：`dsh-qqbot@0.5.5` 的 peer 需 `@deepseek-ai/dsh-llm|dsh-agent|dsh-session >= 0.1.0-rc.6`；按 semver 预发布规则，该区间只会匹配 `0.1.0-rc.x`（同 `major.minor.patch` 才允许预发布），因此在 C1 宿主下 peer 解析结果就是 `0.1.0-rc.8` 同一线；在 0.2.x 宿主下会解析到 **0.1.0-rc.8 的旧线**，形成跨线混装 → 这就是 C3/C4 不能标支持的机制性原因（需 V12 实机确认 pnpm 的 peer 解析行为）。

#### 6.6.5 禁止性规则（写进 `command-policy.ts` 与 code review 清单）

1. 不得对 `owner: 'desktop'` 的 profile 执行任何写操作。
2. 不得使用 `latest`/`alpha`/`next` 标签解析版本；唯一允许的版本来源是清单中的精确串。
3. 不得在未列入 `compat.json` 的组合上安装插件并对外显示"可用"。
4. 不得用 `--from-default-profile` 作为回滚手段（F15）；回滚 = 恢复我方备份目录。
5. 不得内置、镜像、转存 Desktop 安装包或任何 `UNLICENSED` 依赖（见 02 §6）。

### 6.7 陪伴能力的落地形态（与 02 §2.3 对应）

结论：**V0.1 的"陪伴基础套装"= 配置 + 提示词 + 原生能力开关，不是插件集合**。逐项依据见 02 §2.3。

| 能力 | 承载方式 | 我方交付物 | 是否需要第三方插件 |
|---|---|---|---|
| 人设 | 宿主原生 `@deepseek-ai/dsh-persona`（preset 行，注册人设前缀/后缀） | 人设配置文件 + 预制提示词（`resources/prompts/persona-*.md`） | 否 |
| 长期记忆 | 宿主原生会话持久化 + `compaction` 包组；可选接第三方记忆 MCP | "记忆说明 + 可选 MCP 配置片段"，**不代装 MCP 服务器**（官方明确 DSH 不负责下载） | 否（可选，用户自备） |
| 陪聊 | 模型 provider 配置 + `dsh-qqbot` 的 `groupPrompt`/`directPrompt`/`requireMention`/`access.*` | 配置模板 + 引导页（配置项含义与推荐值） | 否（复用核心插件配置） |
| 主动互动 | 宿主原生 `schedule` 服务 + `schedule_*` 工具（`standard`/`cordis`/`ptc` preset 自带）+ 自动化任务页 | "定时提醒"配置方案 + 提示词模板（不写调度器） | 否 |

因此 V0.1 核心插件套装只有 `@tencent-connect/dsh-qqbot` 一项 + 若干配置/提示词产物，与产品决策 A 方案（只维护经验证的核心套装）一致。

## 11. 安全设计

### 11.1 密钥

- DeepSeek API Key、QQ AppSecret 只经 `secret:set` 进入主进程 → `safeStorage.encryptString` → `secrets.bin`。
- 回传渲染层仅返回 `{ masked: "sk-****abcd" }`。
- 日志脱敏：`redact.ts` 对已知字段名（`apiKey|secret|token|authorization`）与内存中已知密钥值做双重替换。
- **密钥不经我们的服务器**，不做任何遥测上报。

### 11.2 进程执行

- 一律 `spawn(exe, args, { shell: false, windowsHide: true })`，**禁止 `shell: true`**（防命令注入）。
- 参数数组由代码构造；用户输入只作为"值"出现在已定义位置，绝不拼接命令串。
- 子进程 `env`：仅在上层 PATH 前插入自管 `runtimes/*`，不改系统。

### 11.3 供应链

- 所有下载：HTTPS + 强制 SHA-256 校验（`timingSafeEqual`）；镜像回退后**仍以清单哈希为准**。
- Manifest 与插件索引随应用发布；远程热更新版本必须携带 ed25519 签名，**验签失败即拒绝整份索引**（与 DSH "一条不合格即整份拒绝"语义一致）。
- 索引结构校验**直接调用官方 `parseMarketIndex(value, indexUrl)`**（首条违规即抛 `MarketIndexError` 并带 JSON path，导致整份索引被拒）；
  安装规格**直接调用 `marketInstallTarget(name, version)`** 得到 `{ spec, registry? }`，不再自行拼接 `name@version` / `git+…#commit`。
  我方只在官方结果之上追加 overlay 字段（分类、验收方式、离线包位置），overlay 与官方索引**分文件存放**，不污染官方结构。
- 解压前校验条目路径：防 zip-slip、拒绝绝对路径 / `..` / 符号链接逃逸、限制解压后总大小。
- 第三方组件许可证全文随包分发至 `resources/licenses/`，并在插件详情页展示（PLG-4 第 6 步）。

### 11.4 窗口安全

`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webSecurity: true`；
禁用 `remote`；CSP 仅允许 `self` 与 `data:` 图标；外链经协议白名单（https/http）后 `shell.openExternal`。

### 11.5 安装 / 卸载的数据安全边界

| 对象 | 我方可以 | 我方绝不可以 |
|---|---|---|
| 我方安装目录 `%LOCALAPPDATA%\Programs\DeepSeekDeployAssistant` | 安装、升级、卸载时整目录管理 | 写入用户文档目录、写入系统目录 |
| 我方数据目录 `%LOCALAPPDATA%\DeepSeekDeployAssistant\` | 创建、读取、按卸载选项删除 | 删除不属于本应用的子目录（校验归属标记 `dda-owner.json`） |
| 自管运行时 `runtimes\*` | 创建、按卸载选项删除 | 写入系统 PATH / 注册表 / 覆盖同名系统运行时 |
| 用户已有 Node/Python/Git | 只读探测；**最多在子进程 PATH 前置自管目录** | 升级、卸载、改注册表、改用户环境变量 |
| `<home>\profiles\web`（我方 profile） | 创建、备份、安装插件、卸载时询问后删除 | 删除 `<home>` 其他 profile（尤其 `desktop`） |
| `<home>\profiles\desktop`（Desktop 拥有） | **只读**：列存在性/插件清单 | 任何写操作、备份后"迁移"、复制其凭据 |
| Desktop 安装目录与卸载项 | 只读探测 | 卸载、静默升级、改其更新通道 |
| 密钥 | 写入 `secrets.bin`（DPAPI） | 明文落盘/日志/回传渲染层/上传服务器 |
| 日志与诊断包 | 脱敏后导出 | 含密钥、含完整 URL 查询串凭据、含用户文档内容 |

**卸载语义（写死，不提供"深度清理"开关）**：默认只删应用目录与我方数据目录；`runtimes\`、`plugins\offline\`、`profiles\web`、`profiles-backup\` 四项逐项询问，默认保留；
**任何情况下不触碰** `<home>` 下的非 `web` profile、Desktop 安装目录、用户全局 npm/pnpm 目录。

### 11.6 第三方许可门禁（构建期强制执行）

`scripts/license-gate.ts` 在 CI 与打包前对**依赖闭包**逐项解析 `license` 字段，规则：

1. 允许清单：`MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / PSF-2.0 / Unlicense / 0BSD`。
2. 灰名单：`GPL-*、LGPL-*、AGPL-*、CC-BY-NC-*、自定义许可` → 必须进入 `licenses/allowlist.json` 且写明"仅聚合分发/仅运行期下载"的处置方式，否则构建失败。
3. **`UNLICENSED` / 无 `license` 字段 / `"private": true` → 一律视为不可再分发**：禁止进入离线包，只能"运行期从 registry 安装"。
   > 当前命中项：`@tencent-connect/qqbot-connector@1.2.0`（`dsh-qqbot` 的运行时依赖）为 `UNLICENSED`。
   > 影响：**"完整离线安装 QQ 插件"在许可澄清前不可交付**（见 02 §6、03 V11）。
4. 每个进入分发包的第三方包，其许可全文与来源写进 `THIRD_PARTY_NOTICES.md`，并随安装包分发。

## 12. 设计决策记录（ADR）

| ID | 决策 | 理由 | 代价 |
|---|---|---|---|
| ADR-001 | 不自研安装器，`manifest + 官方 CLI/官方发行包` 驱动 | 复用官方渠道，减少维护面（PRD 8 第 4 条） | 受第三方发布节奏约束，必须版本固定 |
| ADR-002 | 插件安装只走 `dsh plugin`，不直接写 profile 目录 | 官方唯一文档化接口（转发 pnpm） | 依赖 pnpm 与 registry 可达 → 必须做镜像与离线包 |
| ADR-003 | 组件下载自研精简下载器（`.part` + Range + 镜像回退），不复用 electron-updater | electron-updater 面向**本应用自身**的 blockmap 差分更新，不适用于任意第三方文件 | 约 300 行自研 + 单测 |
| ADR-004 | 插件状态用"五段证据"而非单一枚举 | PRD 5.5 明确禁止"下载完成 = 部署成功" | 数据模型与 UI 略复杂 |
| ADR-005 | 个人 QQ 用 Port + `unsupported` 桩实现 | 无合规可预置网关（NapCat 禁商用、Lagrange 已 sunset、go-cqhttp 停维护） | 模式 B 在 V0.1 仅做引导 |
| ADR-006 | per-user 安装、永不请求 UAC | 目标用户零基础，UAC 是高弃装点；也满足"不擅自改系统" | WinGet / 系统级安装不可用，需降级引导 |
| ADR-007 | 不预置任何第三方 QQ 网关二进制 | 许可风险（见 02） | 用户需自行下载，体验下降，但规避法律风险 |
| ADR-008 | 资源中心产出 **DSH 兼容 index.json** + 我方 overlay | 直接复用 Harness "发现"页与安装链路 | 需跟随 index format 版本变化 |
| ADR-009 | 长任务放 `utilityProcess` | 主进程保持响应、崩溃隔离 | 多一层消息协议 |
| ADR-010 | V0.1 以 **CLI 路线**作为唯一自动化部署路线；Desktop 只做检测与引导 | Desktop profile 对 CLI 封闭（F9），且其安装包 588 MB 由官方 CDN 分发（F18） | 已装 Desktop 的用户能力受限；需两套 UI 分支 |
| ADR-011 | 索引 schema 与安装规格复用官方 `dsh-plugin-market-index` | 规则由上游维护，避免版本漂移（F12） | 跟随其 minor 升级；overlay 需分文件 |
| ADR-012 | 版本组合走**白名单矩阵**（`compat.json`），拒绝任何 dist-tag 解析 | `latest` 即 prerelease，且 qqbot 只声明特定宿主版本（F10/F11、§6.6.4） | 上游发版时需要人工复核并更新矩阵 |
| ADR-016 | 兼容矩阵只认本机复现过的组合，条目必须带 `evidence` | M0 实测：上游"已验证"与 0.1.0-rc.8 崩溃不一致 | 每次上游发版都要人工复现 |
| ADR-013 | profile 重置只用官方命令且必须二次确认；回滚一律用我方备份 | 该命令会替换并删除目标目录（F15） | 需额外磁盘空间存放 profile 备份 |
| ADR-014 | 我方索引同时提供"文件产物 + 本地 HTTP 托管"并注册进 profile `indexes` | `indexes` 只接受 http(s)（F14）；本地托管让离线用户也能在官方"发现"页看到策展清单 | 需管理本地端口生命周期 |
| ADR-015 | `UNLICENSED`/无许可依赖不进离线包，只允许运行期安装 | `qqbot-connector` 为 `UNLICENSED`（§11.6） | 离线打包能力受限，需许可澄清 |

## 13. 工程约束

- **TypeScript strict** + `noUncheckedIndexedAccess`；禁止 `any`（CI 拦截）。
- 单测：`core` 覆盖率 ≥ 80%（纯逻辑好测）；`adapters` 通过注入 `SpawnFn`/`FetchFn` 打桩，CI 不触网。
- 集成测试：真实 `dsh` 探测与插件列表，跑在独立 `integration` job（允许网络，允许跳过）。
- 所有 IPC 必须有 spec schema + zod parse；**未注册通道默认拒绝**。
- 提交前钩子：`lint` + `typecheck` + `verify-manifests` + `license-gate`。
- **兼容矩阵回归**：`manifests/harness/compat.json` 每次变更必须附一条 `evidence`（上游声明链接/实测记录 id），无 evidence 的条目在 CI 被拒。
