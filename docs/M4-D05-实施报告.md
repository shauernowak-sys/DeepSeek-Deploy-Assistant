## 1. 离线打包（[packages/core/src/market/offline.ts](../packages/core/src/market/offline.ts)）

```
distributionPolicyForEntry(entry)
  ├─ 闭包全允许 + license.redistributable → allowed: ['online-install','offline-bundle']
  └─ 否则                                 → allowed: ['online-install']，blocked 逐项点名
buildOfflineBundle({entry, files, outDir})
  ① assertDistributionAllowed(policy, 'offline-bundle')   ← 复用 D11 门禁，不新增第二套规则
  ② 逐文件写盘（临时文件 + rename）、计算 sha256
  ③ 生成 bundle.json（逐文件哈希 + 整包指纹），路径穿越直接拒绝
```

关键点：**没有第二条许可判定逻辑**。D05 只是把 catalog 事实翻译成 `DistributionPolicy`，判定仍由 D11 的
`assertDistributionAllowed()` 执行——将来若为某条目打开离线能力却忘记过门禁，测试与运行期都会拦下。

## 2. 内容寻址缓存（[market-cache.ts](../packages/core/src/market/market-cache.ts)）

| 行为 | 规则 |
|---|---|
| 写入 | 先校验源文件哈希；复制后再复算；不一致即拒（宁可不缓存） |
| 命中 | **重新计算哈希**；不一致 → 删除并返回 miss（CN-6） |
| 键 | `sha256` 十六进制，非法键直接拒绝（防路径注入） |

## 3. 离线安装（D03 本地模式）

`installCatalogPlugin` 新增：

- 请求字段 `localSpec`（绝对路径 `.tgz`）；依赖 `installLocal()`
- 第 3 步：解析为本地路径；第 4 步：`skipped`（"离线模式：不使用 registry"）；第 5 步：调用 `installLocal`
- 结果新增 `installSource: 'registry' | 'local-file'`，`registry` 变为可选（离线时不存在）

这样"安装成功"的证据链仍是同一条 9 步流水线（第 1 步 compat、第 6 步复核都不跳过），只是来源不同。

## 5. 验收对照

| 计划测试标准 | 证据 |
|---|---|
| ① 含 `UNLICENSED` 的条目，离线打包 API 拒绝并给出包名 | 单测：`E_DISTRIBUTION_BLOCKED`，消息含 `@tencent-connect/qqbot-connector`，且输出目录都未被创建 |
| ② 断网 + 缓存命中 → 安装成功 | D03 本地模式单测：`installSource='local-file'`、registry 步骤 `skipped`、`addPlugin` 未被调用；缓存命中路径由 `getCachedFile`（含哈希复校验）保证 |
| ③ 缓存被篡改 → 淘汰并重新下载 | 单测：篡改后 `getCachedFile` 返回 miss 且文件被删除；`assertCachedTarball` 抛 `E_HASH_MISMATCH` 并删除 |
| ④ QQ 条目 UI 无离线入口 | 码级契约：`distributionPolicyForEntry(QQ).allowed` 不含 `offline-bundle`；catalog `redistributable=false` 且 `installNotes` 写明"不提供离线包"（D02 实现 UI 时以这两个字段为准） |

## 6. 明确未做

1. **依赖预取（`pnpm fetch` 式）**：计划要求"仅在门禁通过时启用"；当前没有允许离线的条目，故未实现（避免成为死代码）。
   接口位在 `buildOfflineBundle` 的文件清单上，加入条目后可直接使用。
2. **UI 的离线按钮/入口**（D02）；本轮不新增死 IPC。
3. `licenses/` 目录与 `node.json` 引用的 `licenses/node-LICENSE.txt`：本轮补齐了 `THIRD_PARTY_NOTICES.md`，
   许可**全文**的落盘（audit SEC-LIC 的另一半）仍未做 —— 需要引入官方发行包内的许可全文，属独立交付项。
4. 离线缓存清理策略（容量上限/最久未用）：当前只做正确性（哈希校验），不做容量管理。
