## 3. 许可全文交付（③）

### 3.1 产出

| 文件 | 内容 |
|---|---|
| `licenses/README.md` | 许可全文索引（文件 ↔ 包 ↔ 版本 ↔ SPDX ↔ 来源），脚本生成，无时间戳 |
| `licenses/node-LICENSE.txt` | Node.js 官方发行包 `LICENSE` 原文（含其自带组件许可） |
| `licenses/pnpm-LICENSE.txt` | pnpm 官方发行包 `LICENSE` |
| `licenses/dsh-LICENSE.txt` | `@deepseek-ai/dsh@0.2.0-rc.2` 的 `LICENSE` |
| `licenses/npm/<name>@<version>.txt` | 10 个生产依赖各自的 `LICENSE` 原文 |

### 3.2 生成与门禁

- `scripts/build-licenses.ts`：许可全文**只从真实发行物读取**（`node_modules/<pkg>` 与用户机器上的官方运行时目录），不生成、不猜测；无文件即报错。
- `npm run licenses:build` 写入并清理过期文件；`npm run licenses:check` 只比对，不一致 exit 1。
- CI `quality` 任务新增 **License texts check**；`npm run verify` 链末尾追加 `licenses:check`。
- 校验项：① 每个包都有全文且与来源一致；② `README.md` 与闭包一致；③ 清单直接引用的运行时文件（`node.json` → `licenses/node-LICENSE.txt`）必须存在；④ 无多余文件。
- CI 机器没有私有运行时目录时：若已提交文件存在则**沿用并打印"未重新校验来源"**，不静默当作通过。

### 3.3 随包分发（实测）

`electron-builder.yml` 的 `extraResources` 增加 `licenses → licenses`。本机 `npm run dist:dir` 后：

```
release/win-unpacked/resources/licenses/node-LICENSE.txt      → 存在
release/win-unpacked/resources/licenses/                       → 14 个文件
release/win-unpacked/resources/THIRD_PARTY_NOTICES.md          → 存在
```

`THIRD_PARTY_NOTICES.md` 的"运行时"段已改为直接指向 `licenses/` 下的三份全文，避免"清单说了但拿不到原文"。

### 3.4 仍需如实说明的局限

- `AppPaths.licenses`（`%LOCALAPPDATA%\DeepSeekDeployAssistant\licenses`）**本版仍未写入**：全文随安装包放在 `resources/licenses/`，未复制到用户目录。`node.json` 的 `textFile` 以"打包根"为基准成立。
- 被拒条目（`@tencent-connect/qqbot-connector`：`UNLICENSED`；`dsh-qq-link`：上游获取）**不提供全文**——本软件不分发其字节，提供原文反而会误导"我们有权分发"。
- 产品闭包当前无 Apache-2.0 组件；`renderThirdPartyNotices()` 的"含 Apache-2.0 需随附 NOTICE"分支保留但本次未触发。
