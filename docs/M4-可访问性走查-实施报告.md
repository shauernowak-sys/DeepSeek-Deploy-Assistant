| 要求 | 验证方式 | 结果 |
|---|---|---|
| 100% / 125% / 150% 缩放不破版 | **真实 DPI**：每个档位单独启动 Electron，带 `--force-device-scale-factor=1\|1.25\|1.5`；断言 `devicePixelRatio` 等于目标值、文档无横向溢出、弹窗左右边界在视口内 | 三档均通过 |

> 为什么不用 `element.focus()` 检查焦点环：程序化聚焦不会触发 `:focus-visible`，检查会变成自欺。同理也不用 CSS `zoom` 假装缩放——`devicePixelRatio` 才是用户看到的那一档。

## 2. 走查暴露的缺口（本轮修复）

原来的弹窗只有鼠标可用：没有 `role="dialog"`/`aria-modal`、打开后焦点留在背景、Esc 关不掉、关掉后焦点掉到 `body`。这些都是键盘用户直接撞墙的问题。

### 2.1 修复（`apps/desktop/src/renderer/src/App.tsx`）

| 改动 | 说明 |
|---|---|
| `role="dialog" aria-modal="true" tabIndex={-1}` | 5 个弹窗统一（取消/诊断/回滚/部署/恢复） |
| 打开时焦点移入弹窗 | 优先聚焦第一个可聚焦元素（恢复弹窗里是备份单选框） |
| **Esc 关闭** | 正在执行动作时（`busy` 有值）不响应，避免中断写操作 |
| **焦点陷阱** | Tab / Shift+Tab 在弹窗内循环，焦点不会跑到背后页面（`aria-modal` 才名副其实） |
| **关闭后焦点归还** | 用一个 `focusin` 监听记住"打开前焦点在哪"，关闭时延后一拍还回去 |
| 回滚确认弹窗补一句文案 | "回滚完成后可直接点『开始部署』重新安装：下载与包缓存会保留" |

两个实现坑（都已固化在代码注释里）：

1. **不能在 effect 里读 `document.activeElement`**：打开弹窗时触发按钮会因为 `busy` 置灰，浏览器先把焦点丢到 `body`，读到的是空——必须用 `focusin` 提前记录；
2. **焦点归还必须延后**：弹窗节点被移除的瞬间浏览器把焦点设到 `body`，同一个同步 tick 里 `focus()` 会被覆盖，需 `setTimeout(0)`。

## 5. 现状与边界

- **§21.12 四项均已按上表方式验证通过**，矩阵状态由 `未验证` 改为**已完成**，证据列指向本轮日志与截图。
- **新增实时播报（aria-live）**：`role="status" aria-live="polite" aria-atomic="true"` 的阶段播报区域（只在**步骤状态变化**时更新，不随进度百分比刷屏）+ `notice` 用 `role="status"`、错误卡用 `role="alert"`；5 个弹窗补 `aria-labelledby` 指向标题（读屏不再只说"对话框"）。
- **无障碍树校验已进脚本**：走查用 CDP `Accessibility.getFullAXTree` 断言"按钮都有可访问名称""存在 live=polite + atomic 的实时区域且内容像进度""弹窗 dialog 有名称且 modal=true"。预置失败任务让播报内容可核对：`第 2/3 步：下载 Node 运行时，失败`。
- 但**这不等于"无障碍合规"**：CDP 无障碍树是"读屏会读到什么"的可复现代理，**Narrator / NVDA 的人工听读实测仍未做**（需要安装读屏软件与人工判断），本轮不宣称通过。若需要合规结论，应另立"屏幕阅读器实测"任务。
- "重置安装"仍是产品决策（草案已提交），矩阵 §21.10 保持**部分完成**（3/4 入口可用）。
