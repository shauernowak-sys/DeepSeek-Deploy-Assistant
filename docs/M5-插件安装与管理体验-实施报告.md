「插件资源」现在是**找插件 / 我的插件**两个入口：用户能看懂每个插件是做什么的、点一次就能装上受支持的插件、安装后能直接打开**插件自己的真实设置页**、按**真实运行截图**一步步配置、并且能在卸载前看清哪些数据会被保留。

## 1. 开发前必须查清的问题（实测结论）

### 1.1 Harness 的启动与配置环境

- 本软件启动 Harness 的唯一入口是 `HarnessService.launch()` → `createDshCli().launchWeb()`，执行
  `node <dsh bin.js> --profile web --no-open --port 0`，并把 `DSH_HOME` 指向本软件数据目录，因此
  **插件装的环境和打开设置的环境是同一个 `web` profile**（`apps/desktop/src/main/services/harness-service.ts`）。
- 启动后 dsh 会打印 `http://127.0.0.1:<port>/?token=<...>`；该地址换取签名 cookie 后跳转到 `/`。
  本软件把这个带 token 的地址交给系统浏览器，浏览器与插件管理页因此处于同一会话（实测可行）。
- **没有**可用的深链接：`0.2.1-rc.3` 的网页端是单页应用，面板切换只存在于内存状态，
  HTML/客户端 bundle 里没有 `location.hash` 或 `?panel=` 之类的入口（实测：改 hash 不切换面板）。
  所以「打开设置」= 打开 Harness 首页 + 明确告诉用户点左侧栏哪一项；**不拼接猜测地址**。

### 1.2 插件管理能力（`0.2.1-rc.3`）

- 网页左侧栏有「插件」面板：安装、启用/停用开关、每个插件的配置页（`@deepseek-ai/dsh-plugin-manager`）。
- 命令行只有 `dsh plugin --profile <p> <pnpm 参数>`（add / remove / list…），**没有** enable/disable 子命令；
  启用状态由 web 配置环境里的配置决定。因此本轮**不提供**「启用 / 停用」按钮，避免做了却没真正生效。
- 「已加载」有权威信号：Harness 页面 HTML 里的 `plugins/??<包名>/client.js` 列表只包含**已挂载**的插件。
  本软件用这一点判断加载状态（同一进程、同一 token、本机回环，不经代理）。

### 1.4 AuraBot 人设：真实操作方式

- 面板分组：`概览 / 人设 / 表达 / 平台 / 系统`；人设组里是 `人格 / 聊天 / 主动搭话 / 心情与记忆`。
- **必须先完成 5 步设置向导**（你们的 QQ 号 → 接 QQ 网关 → 启动并同意协议 → 连上机器人号 → 完成）才出现这些标签页
  （源码依据：`client/client.js` 里 `showWizard = !cfg.setupDone || wizardOpen`，导航栏在向导关闭后才渲染）。

- 数据位置（实测）：`$DSH_HOME/plugins-data/aurabot/`，人设是 `personas/*.md`，配置在 `config.json`（含 `setupDone`、`persona.current`）。
- 本轮**没有**实现第二套人设系统；本软件只负责把用户送到这个界面。

### 2.5 卸载与数据保护

流程：**确认 → 备份 profile → 停止 Harness（Windows 上运行中的进程会占住文件）→ 官方 `plugin remove` → 恢复运行 → 重新读状态**。

- 未确认不动手；备份失败**中止卸载**（不写任何东西）；
- 只删用户选中的那一个包名，不通配、不碰 `plugins-data` 与用户文件；
- 卸载说明来自实测：Aurabot 的设置在 `plugins-data\aurabot`，卸载后仍保留；官方 QQ 插件的平台授权不由本软件控制。

## 3. 本轮修掉的四个真实缺陷

1. **卸载时没有先停 Harness**：Windows 下 profile 里的文件被运行中的 Harness 占住，`pnpm remove` 直接失败。
   现在先 `stop()` 再删，成功后按原状重启；失败时也尽量恢复运行并给出原因。
2. **`ERR_PNPM_UNEXPECTED_STORE`**：profile 的 `node_modules` 是从某个 store 链接来的，换了 store 位置再增删会被 pnpm 拒绝
   （用户换过 pnpm 配置、或用 Harness 自己的界面装过插件时都可能发生）。现在从 `node_modules/.modules.yaml` 读回
   `storeDir`，安装与卸载都带上 `--store-dir=<原值>`；仍失败时把这条错误翻译成可执行的下一步，并附上安装器日志尾部。
3. **全新环境首次安装会被误判为失败**：第 8 步「配置自检」在补丁里没有 `im-qqbot` 条目时直接报错
   （`第 8 步（config）失败：补丁中没有 im-qqbot 条目`），而首次安装本来就不该有配置。
   现在区分「尚未配置」（正常，步骤通过并注明下一步）与「已配置但字段不合法」（失败并带原因）。
4. **渲染层 `navigator.clipboard` 会静默失败**：窗口未聚焦/无权限时复制被拒绝，用户点「复制」只看到失败提示。
   现在复制走主进程 `clipboard.writeText`（IPC `clipboard:write`，zod 校验长度），实测剪贴板内容正确。

## 7. 仍然受限 / 待人工验收

1. **真实 QQ**：扫码绑定、群聊/私聊收发、图片消息——需要真人手机 QQ，本轮全部未做。
2. **Aurabot 真实网关**：本地模拟 OneBot 只能证明「装了、能加载、向导与人设可用」，不能证明真实 QQ 会话质量；
   其 SnowLuma 管理与本项目 EULA 授权边界的关系仍需产品/法务确认。
3. **一键安装**：目前只对 `@tencent-connect/dsh-qqbot@0.5.5` 开放。Aurabot 仍是 `needs-review`（上游未声明兼容、素材许可、
   闭包未审计），所以「找插件」里只有说明与手动方式，没有安装按钮。
4. **启用 / 停用**：`dsh` 没有对应子命令，本轮未提供；需要真正做的话要先确认写配置的方式与回滚。
5. **插件管理页深链接**：上游不支持，只能打开 Harness 首页 + 图文指引。
6. 其它 12 条候选的安装、设置入口与引导均未验证，界面里如实标注。

## 9. 复现要点（给下一位）

```powershell
# 隔离环境：同一份 profile 既装插件又开设置，避免「装一套、开另一套」
$env:DSH_HOME = "<root>\dsh-home"
& node <root>\harness\node_modules\@deepseek-ai\dsh\lib\bin.js --profile web --no-open --port 0

# 本软件端（隔离 LOCALAPPDATA，不碰真实环境）
$env:LOCALAPPDATA = "<root>\dda-m5-app"
npx electron . --user-data-dir="<root>\userdata" --remote-debugging-port=94xx
```

> 提示：`--user-data-dir` 必须显式给，否则会和 `%APPDATA%` 里遗留的旧单实例锁冲突，表现为「启动后立刻退出、没有任何日志」。
