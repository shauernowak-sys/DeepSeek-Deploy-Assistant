## 0. 一页结论

| 架构问题 | 决策 | 依据 | 置信度 |
|---|---|---|---|
| 索引格式 | **官方 format 1（`parseMarketIndex` 校验）+ 我方 overlay（zod）并存** | 官方格式无许可/哈希/依赖/验收字段，且多余字段被静默丢弃 | 高（已实测） |
| 索引托管 | **随包内置 + 我方静态托管（CDN/对象存储）**；**不注册到 Harness** | 锁定版 `0.2.0-rc.2` 无索引读取方 | 高（已实测） |
| 插件目录（策展） | **我方维护 `catalog.json`（源码内静态）**，构建期生成 `index.json` | 需要中文、分类、许可、验收方式等官方格式装不下的信息 | 高 |
| 安装执行 | **`dsh plugin --profile web add <精确 spec>`（我方编排）+ Harness Web 插件管理页（用户自助）** | CLI 与 Web 走同一 `pluginManager.installBundle`，实测可用 | 高（CLI 端到端已实测） |
| Agent 安装 | **不作为主路径，标注"未验证"** | `plugin_manager` 默认禁用 + 无 API Key 无法验证回合 | 高（配置级已证实） |
| 状态证据 | **只承诺"已安装 / 已加载"两段为强证据**；其余三段按"弱证据 + 明确未验证"呈现 | 见 §5 | 高（已实测） |
| 许可门禁 | **在线安装放行 + 离线/镜像/重打包一律阻断**（含 `UNLICENSED` 的闭包不可打包）；已落地 `QQ_PLUGIN_DISTRIBUTION` + `assertDistributionAllowed()` + 统一文案 | QQ 插件闭包含 `UNLICENSED`；Gate 4 ② 已降级 | 高（已实测 + 12 项测试） |
| 最终方案 | **方案 B（我方策展 + 用户驱动安装）**，方案 A 顺延 | 见 §7 | 高 |
| 无 VPN 可行性 | **已实测通过**（直连 37/37 安装成功，镜像约快 19 倍） | 见前置验证报告 §4.5 | 高（实测） |

## 2. 插件索引架构

### 2.1 两层文件

| 层 | 文件 | 格式 | 校验方 | 谁读 |
|---|---|---|---|---|
| L1 官方层 | `index.json` | 官方 format 1 | **`parseMarketIndex()`（官方库）+ 我方追加断言** | 我方 UI、未来的 Harness 发现页 |
| L2 overlay 层 | `catalog.zh.json`（或直接编译进 catalog） | 我方 zod schema | `@dda/spec` 的 `CatalogSchema` | 仅我方 |

### 2.2 分工（必须写入代码注释，防止后来者混淆）

**官方库负责（不得重复实现）：**
- `format === 1`、`title` 必填且含 `en`、`plugins[]` 结构
- `name` 的 npm 包名语法与长度
- `version` 精确 SemVer、`versions` 非空/去重/降序
- `publishTimestamp` 整数范围
- `source` 的 npm/git 形态、git commit 40 位小写 hex、URL 规范性与凭据拒绝
- `engines.dsh` 的 SemVer range 语法
- `icon` 的 data URL 类型/32 KiB 上限/跨源 http 拒绝
- `metadata.categories/labels/sortKeys` 的声明-引用一致性
- 相对图标相对索引 URL 的解析

**我方 overlay 负责（官方格式无承载位）：**
| 字段 | 我方要求 |
|---|---|
| `license` | SPDX 标识 + `redistributable: boolean` + `needsReview?: boolean` |
| `integrity` | `sha512-…`（与 registry `dist.integrity` 一致）或 `sha256:…`（离线包） |
| `dependenciesClosure` | 逐项 `name@version` + `license`（D11 门禁输入） |
| `acceptance` | 可执行验收项数组（例如"发送群 @ 消息并收到回复"） |
| `compatCombination` | 指向 `compat.json` 的 `entry.id`（dsh×qqbot×node 三元组） |
| `zh` | 中文标题/描述/用例引导（官方 `title` 只能放 `en` + `zh` 两键，中文长文案放 overlay 更自由） |
| `safety` | 风险提示（如"加载即向厂商服务器发起绑定请求"） |
| `installNotes` | 需要的环境变量/重启要求 |

> **硬规则：** overlay 字段**不得**塞进 `index.json` 冒充官方字段（会被静默丢弃，造成"看起来配了、实际丢失"的假象）。

### 2.3 索引托管（三类，按可用性排序）

| 层 | 位置 | 何时用 | 备注 |
|---|---|---|---|
| 内置 | 随安装包（`resources/market/index.json`） | **首选**，永远可用 | 满足 PRD CN-7"索引可达性"：断网也不空白 |
| 静态托管 | 我方对象存储 + CDN（U5 待决） | 需要热更新时 | 只放索引与图标，**不放任何插件产物**（避免再分发） |
| 远程自定义 | 用户/产品配置的 URL | **不在 V0.1 开放** | 开放即引入 U14/SEC-9/10（签名+防回滚） |

**索引更新策略：** 内置索引为"最小可信集"，远程索引仅用于"新增条目提示"，且必须校验签名/哈希后才能并入展示（U14 未决前，远程索引仅提示"有新版本可用"，不可直接安装）。

### 2.4 图标

- 官方限制 32 KiB（decoded）。建议：**图标统一放在索引同源目录**，使用相对路径；**不使用 data URL**（会让 index.json 膨胀且不可缓存）。
- 我方构建期检查：文件存在、MIME 为 png/svg、decoded ≤ 32 KiB、尺寸 ≤ 256×256。

## 3. 插件目录（catalog）架构

### 3.1 目录条目（我方首选形态）

```
catalog/
├─ entries/
│  ├─ official-qqbot.ts        # 单条目的唯一事实来源
│  └─ …
├─ icons/                      # 与索引同源
└─ index.ts                    # 汇总导出 + 构建期校验
```

单条目字段（源码内类型，构建期 zod 解析）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 稳定 id（`plg-official-qqbot`），**不要用包名当 id**（包名可能变） |
| `name` / `version` | ✅ | npm 包名 + 精确版本（禁止 range、禁止 `latest`） |
| `source` | ✅ | `{type:'npm', registry?}` 或 `{type:'git', url, commit}` |
| `compat` | ✅ | 指向 `compat.json` 的 `entry.id`，且该条目必须 `verified-local` |
| `license` | ✅ | SPDX + `redistributable` |
| `integrity` | ✅ | 与 registry 一致的 `sha512` |
| `depsClosure` | ✅ | 由 D11 在构建期生成（快照） |
| `acceptance` | ✅ | 至少 1 条可执行检查 |
| `zh` | ✅ | 名称/一句话用途/详细说明/使用场景/风险提示 |
| `category` | ✅ | 引用索引声明的 category id |
| `safety` | ✅ | 外联行为、权限要求、是否需要重启 |
| `status` | ✅ | `verified` / `needs-review` / `blocked`；**只有 `verified` 可展示安装按钮** |

### 3.2 首批条目（V0.1 范围）

PRD §10.5 已冻结"10 项核心资源"，其中**只有 1 项是真插件**：

| 资源 | 承载方式 | 是否进 M4 目录 |
|---|---|---|
| Harness 本体 / Node / pnpm | 外部依赖/私有运行时 | ❌ 不是插件（属 M1/M2） |
| 官方 QQ 接入组件 | 独立插件 `@tencent-connect/dsh-qqbot@0.5.5` | ✅ **唯一首批插件** |
| 人设 / 记忆 / 主动互动 | 宿主原生能力 | ❌ 不写成插件（CR-1） |
| 陪聊配置 / 预制提示词 | 配置文件/提示词 | ❌ 走配置页，不走插件目录 |
| 必要辅助组件 | 未纳入 V0.1 | ❌ |

→ **M4 的"目录"在 V0.1 只有一个真实条目**。这不是缺陷，而是冻结范围的结果；UI 文案必须避免暗示"海量插件市场"。

## 4. 安装架构

### 4.1 安装执行器选择（三选一，已实测）

| 选项 | 可行性 | 优点 | 缺点 | 采用 |
|---|---|---|---|---|
| A. `dsh plugin --profile web add <spec>` | ✅ 实测成功（npm / npmmirror / GitHub） | 与 Harness 官方同一服务；有 profile 锁、日志、兼容性预检、版本豁免 | CLI 输出需解析；无结构化返回 | **✅ 主路径** |
| B. Harness Web 插件管理 UI（`ui-plugin-manager`） | ✅ 默认启用 | 官方维护、有安装对话框与审批 | **用户在另一个应用里操作**；我方无法自动驱动 | **✅ 辅助路径**（"在 Harness 中打开"） |
| C. `plugin_manager` Agent 工具 | ⚠️ 存在但默认禁用 | 可自然语言 | 未启用 + 无 API Key 无法验证 + 高危权限 | **❌ 不作主路径** |

### 4.2 编排步骤（D03，对齐 PLG-4 的 9 步）

| 步 | 动作 | 失败语义 | 可否重试该步 |
|---|---|---|---|
| 1 | **compat 白名单**：`assertCombination(dsh, qqbot, node)` | `E_VERSION_UNSUPPORTED` + 具体组合 id | 否（需改组合） |
| 2 | 预检：profile 可写、磁盘余量、registry 可达（HEAD 元数据） | `E_PRECHECK_*` | 是 |
| 3 | 解析安装 spec（`parseInstallSpec` 等价位逻辑） | `E_INVALID_SPEC` + 人读原因 | 否 |
| 4 | registry 计划（`registry` + `fallbackRegistries`） | — | 是（换源） |
| 5 | 执行 `dsh plugin add <spec>`（带超时与输出流） | 归因：registry / spec-host / other | 是 |
| 6 | 安装复核：`dsh plugin list` + profile `package.json` + `node_modules` | `E_VERIFY_*` | 是 |
| 7 | 加载复核：dump-config 出现该 bundle 的插入行（或 Web API `listBundles().enabled`） | `E_LOAD_*` | 是（需重启 Host） |
| 8 | 配置自检：所需字段存在且格式合法（**不是"生效"**） | `E_CONFIG_INCOMPLETE` | 是 |
| 9 | 连通探测：仅在能力具备时执行，否则明确"未验证" | 不判失败，只标"未验证" | — |

**强制规则：**
- **任一步失败可定位到步号**，且**只重试该步**（`retries` 按步配置）。
- **步骤 1 必须在任何 pnpm 调用之前**（否则会出现"装上了但被门禁判非法"的两难）。
- **步骤 9 不允许伪造成功**（`已连通` 只由真实收发/真实探测产生）。

### 4.3 registry 策略（D06，含现网缺陷修复）

**实测规则：** `registryPlan()` 只在"pnpm 自身 registry 是官方 npm **或** 在 fallback 列表里"时才返回多源回退顺序；否则**单独询问**。

**无 VPN 直连实测（2026-11-04）：** 插件主包 tarball 从 npmmirror 下载 **624 KiB/s**，从 registry.npmjs.org **33 KiB/s**（约 19 倍差）；元数据 46 ms vs 884 ms。两源字节与 integrity 完全一致。→ **"镜像优先 + 官方兜底"有实测依据。**

**同时发现两个必须处理的现实问题：**

| 问题 | 现象 | D06 要求 |
|---|---|---|
| **配置镜像 ≠ 全部走镜像** | registry 设为 npmmirror 时，仍多次从 `registry.npmjs.org` 下载部分 tarball（1–43 KiB/s）；但直接查 npmmirror packument，`dist.tarball` 全部指向 npmmirror → 疑似 pnpm 跨源元数据缓存复用 | ① 记录**每个 tarball 的实际 host**（pnpm 慢速告警已给出该信息）；② 在**干净机器/干净 pnpm 缓存**上复测；③ 文案不得承诺"全部国内下载" |
| **遗留失效代理** | VPN 客户端关闭后 `HTTP(S)_PROXY` 仍指向死端口时，`npm view` 从 <1 s 退化到 **70.6 s**；而 `dshEnv()` 会把 `process.env` 原样传给 dsh 子进程 | 安装前检测 `HTTP(S)_PROXY`/`ALL_PROXY` 可达性；不可达时**只在子进程**剔除并提示（不改用户系统设置） |

**必须采用的双源配置：**

```ts
// 传给 dsh 子进程
npm_config_registry = 'https://registry.npmjs.org/'      // 让 Harness 认为"自身是公共源"
// profile 级（或调用侧）：
registry          = 'https://registry.npmjs.org/'
fallbackRegistries = ['https://registry.npmmirror.com/']
```

或镜像优先但保留回退：

```ts
registry           = 'https://registry.npmmirror.com/'
fallbackRegistries = ['https://registry.npmmirror.com/', 'https://registry.npmjs.org/']
npm_config_registry = 'https://registry.npmmirror.com/'
```

**现网问题（必须在 D06 修复）：** `container.ts` 默认 `registry='https://registry.npmmirror.com'` 且无 fallback → 按 `registryPlan` 规则会**禁用回退**。修复方式：给 `Container` 增加 `registryFallbacks` 并显式传入 `--registry` 序列，或把 npm_config_registry 固定为官方源。

**PRD 三层（L1/L2/L3）的当前落点：**

| 层 | 现状 | M4 结论 |
|---|---|---|
| L1 我方资源库 | 不存在（U5 未决） | **不实现**，只保留接口位 |
| L2 npmmirror | 可用（integrity 与官配一致） | 作为 fallback 实现 |
| L3 官方 registry | 可用 | 作为首选或兜底 |

### 4.4 本地导入（D04）

- 三种输入：`.zip`、`.tgz`、目录。
- 统一转换：`zip`/目录 → 先打包成 `.tgz`（已有 `zip-writer` 与打包能力可复用/扩展）→ 仅向 pnpm 传**绝对路径**的 `.tgz`（`parseInstallSpec` 要求绝对路径）。
- **强制前置**：我方计算 SHA-256 并与 catalog 记录比对；不一致直接拒绝（这是"清单哈希参与安装"的唯一位置）。

## 5. 状态证据架构（五段）

### 5.1 五段定义与证据等级

| 段 | 定义 | 证据来源 | 等级 | UI 口径 |
|---|---|---|---|---|
| ① 已解析 | catalog 条目通过官方 + overlay 校验，且 compat 命中 | 构建期结果 + 运行时 `assertCombination` | 强 | "已验证" |
| ② 已下载 | 我方下载并校验通过的文件存在且哈希一致 | `sha256File` + 清单 `integrity` | 强（仅限我方下载路径） | "已下载（已校验）" |
| ③ 已安装 | profile `dependencies` + `node_modules` + `dsh plugin list` 一致 | CLI 解析 + 文件 | 强 | "已安装" |
| ④ 已加载 | Host 启动后该 bundle 的条目在组合树中存在，且 `enabled=true`/无 load error | dump-config 或 Web `listBundles()` | 强 | "已加载" |
| ⑤ 已配置 | 插件所需配置字段存在且格式合法 | 我方自检 | **弱（仅"已写入"）** | "配置已写入（未验证生效）" |
| ⑥ 已连通 | 真实功能探测成功（收发/心跳/API 往返） | 真实探测 | 强（但当前不具备） | "未验证" |

> **注意：** 项目内部把五段表述为"已下载/已安装/已加载/已配置/已连通"，加上"已解析"共六项。PRD §10.4 写作"已解析→已下载→已安装→已配置→已连通"。**两套口径必须统一**（见 §9 待决策 Q-3）。本文件按 PRD 五段命名，"已加载"作为"已安装→已配置"之间的**技术子状态**（因为 0.2.0-rc.2 安装即挂载，加载可独立观测，值得单独呈现）。

### 5.2 证据不可得时的呈现规则（硬规则）

1. 证据不可得 → 显示 **`未验证`**，不显示成功、不显示进度条"100%"。
2. 弱证据 → 文案必须带限定词（"配置已写入，未验证生效"）。
3. 任一强证据失败 → 该段标红，且**其后各段一律"未验证"**（不允许"跳过失败继续显示后续成功"）。
4. "已安装" 与 "可用" **不得共用同一视觉**（PRD §10.4 / Gate 4 ④）。

### 5.3 与现有 QQ 相位的映射

| 现有 `QQ_PHASES` | 对应五段 |
|---|---|
| `not-deployed` | ①②③ 全未达成 |
| `not-installed` | ① 达成，②③ 未达成 |
| `installed` | ③ 达成，④⑤⑥ 未知 |
| `connecting` / `binding` | ③ 达成，⑥ 进行中（未验证） |
| `connected` | ③ 达成，⑥ 强证据（仅当来自真实收发/真实心跳） |
| `failed` | 对应段失败 |

→ M4 应把 `QQ_PHASES` **收敛为五段的投影**，避免两套状态机并存（D02 的核心工作）。

## 6. 许可证门禁架构

### 6.1 三条硬规则

| # | 规则 |
|---|---|
| LIC-1 | **在线安装（用户机器从 registry 拉取）允许**，即使闭包含 `UNLICENSED`；我方不复制任何字节 |
| LIC-2 | **任何由我方分发的产物（离线包、L1 镜像、随包内置）必须闭包 100% 在允许列表内**，`UNLICENSED`/`SEE LICENSE IN`/`NOASSERTION`/未声明 一律阻断 |
| LIC-3 | **插件中心不得出现"离线安装"按钮**，除非该条目 D11 门禁已产出"可离线"结论 |

> **已落地（2026-11-04）：** LIC-1~LIC-3 不再只是文字规则，而是 `packages/spec/src/licensing.ts` 的 `QQ_PLUGIN_DISTRIBUTION`（`allowed: ['online-install']`，三种分发方式各自带阻断原因）+ `packages/core/src/market/distribution.ts` 的 `assertDistributionAllowed()`。安装步骤在调用官方命令前先过该门禁；UI（`App.tsx` 许可说明）、部署日志、安装失败提示三处共用同一段 `notice`，不再各写一套。新增错误码 `E_DISTRIBUTION_BLOCKED`。测试：`tests/core/distribution-policy.test.ts`(9) + `tests/desktop/plugin-distribution-gate.test.ts`(3)。

### 6.2 门禁实现（D11）

```
pnpm list --prod --depth Infinity --json（在隔离 profile 内）
  → 逐包解析 package.json license / LICENSE 文件
  → 归一化 SPDX（含 "Apache 2.0" → Apache-2.0 这类别名）
  → 判定 { allowed | needs-review | denied }
  → 产出 depsClosure 快照 → 写入 catalog → 构建期断言
```

**必须扩展到**插件闭包（现 `scripts/license-check.mjs` 只扫本产品闭包）：

| 能力 | 现状 | D11 目标 |
|---|---|---|
| 扫描范围 | 本产品 prod 闭包 | 本产品 + 每个 catalog 条目的插件闭包 |
| 阻断 | 有（`process.exit(1)`） | 有 + 按条目产出报告 |
| 输出 | 控制台 | 控制台 + `THIRD_PARTY_NOTICES.md` 片段 |
| 别名归一化 | 不全（`Apache 2.0` 未覆盖） | 全覆盖 |

## 7. 方案 A / 方案 B 比较与最终推荐

（数据来自 [前置验证报告 §8](./M4-前置验证报告.md#8-v-m4-8产品交互架构验证方案-a-vs-方案-b)）

| 维度 | 方案 A：Harness 原生市场 | 方案 B：我方策展 + 用户驱动安装 |
|---|---|---|
| 锁定版可行性 | **不可能** | 可行 |
| 开发成本 | 需先行升级宿主（`compat.json` 现禁止 0.2.1-rc.5）+ 启用 experimental bundle + 重做验收 | D01/D02/D09/D11 可独立开工 |
| 用户操作 | 在 Harness 内完成（体验统一） | 跨两个应用（差） |
| 插件管理能力 | 受 Harness 限制（0.2.1-rc.5 明确不支持升级） | 我方编排，可控 |
| 维护成本 | 跟随 experimental 接口漂移 | 接口面窄（`plugin add/remove/list`） |
| 安全风险 | 索引无签名、无哈希、用户可自加索引源 | 我方白名单 + 精确版本/commit + 清单哈希 |
| 版本兼容 | 单字段 `engines.dsh` | 三元组 `compat.json` |
| 许可门禁 | 无字段 | overlay 强制 |
| 离线能力 | 无 | 受 `UNLICENSED` 限制（与 A 相同） |

### 最终推荐：**方案 B（含三条修正）**

1. **执行方是"用户明确动作"，不是 Agent**：主路径 `dsh plugin add`（我方编排）；辅助路径"在 Harness 中打开插件管理页"。Agent 路径标注未验证。
2. **索引与安装解耦**：索引只做展示/校验；安装规格由 catalog 产出。
3. **D10 顺延**：宿主升级 + experimental market bundle 之后再评估，且必须重做 QQ 兼容验收。

**方案 A 的保留条件（未来）：** 当且仅当 ① `compat.json` 新增 0.2.1-rc.x 的 `verified-local` 条目；② QQ-GATE-01 在新宿主上重新通过；③ 官方索引格式补上许可/哈希字段（或我方确认 overlay 可接受）。三者任一不满足，不切换。

## 8. 安全边界

| # | 边界 | 实现要求 |
|---|---|---|
| SEC-1 | 只允许 http(s) 与本地绝对路径；拒绝 `file:` 相对、`../` 相对、非 git/tarball 的 URL | 复用 `parseInstallSpec` 规则，不放松 |
| SEC-2 | 只允许白名单内的包名 + 精确版本 / 固定 commit | catalog 是唯一入口；UI 不允许自由输入 spec |
| SEC-3 | 索引无签名 → **不把远程索引当安装依据**；远程索引仅提示 | 远程索引内容不得直接生成可点击的安装动作 |
| SEC-4 | 图标 32 KiB + 同源/https 限制 | 官方校验器已覆盖；我方再加 MIME/尺寸检查 |
| SEC-5 | 插件加载即执行宿主进程内代码 | 详情页**必须**展示该风险；`status != verified` 的条目无安装按钮 |
| SEC-6 | 构建脚本（`allowBuilds`）属于持久授权 | 默认不授权；需要时逐包、逐次提示；授权写入前展示包名 |
| SEC-7 | 失败日志含完整 spec 与 registry | 日志落盘前脱敏（token/凭据），保留 spec 用于复核 |
| SEC-8 | `plugin:install-qq`、`installPlugin(spec)` 等旁路入口 | **必须改为走同一编排器**（含 compat 门禁），或删除（Gate 4 ⑤） |
| SEC-9 | 不修改 `desktop` profile | 已有 `E_PROFILE_OWNED_BY_DESKTOP` 保护，M4 保持 |
| SEC-10 | 不启动本地索引服务 | 锁定版无消费方；启动只会徒增攻击面（D10 顺延的直接收益） |

## 11. 不可行 / 不采用清单（明确记录，避免返工）

| 项 | 结论 | 原因 |
|---|---|---|
| 锁定版注册本地插件索引（D10 原形态） | **不可行** | 无索引读取方 |
| 通过 patch 注入市场服务到锁定版 | **不做** | 需要把整个 market 包塞进 profile，属非官方注入，且 experimental |
| 依赖 Agent 完成安装 | **不作为主路径** | 工具默认禁用、未验证、需高危权限 |
| 离线分发 QQ 插件 | **不可行** | 闭包含 `UNLICENSED` |
| 在索引里写 `license`/`hash` 并期待 Harness 使用 | **无效** | 多余字段被静默丢弃 |
| 用 `latest`/range 安装 | **禁止** | PRD CN-2；且 `dsh@latest` 已是未验证的 0.2.1-rc.5 |
