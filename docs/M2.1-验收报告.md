## 5. 是否可以进入 M3

**可以进入 M3 的开发，但 M3 的验收标准必须包含以下前置项：**

1. **QQ-GATE-01**（真实凭据 + 手机）：任何"官方 QQ 可用"的对外表述都以此为前置。
2. **API Key 真实连接测试**：PRD §11 的必需能力，M2 明确未实现，属 M3 首个补齐项。
3. **干净 Win11 第二环境**：按审计报告 §6.4 的方案执行，不得用本机结果替代。
4. **代码签名**：S1（OV）排期确定，否则 SmartScreen 会持续拦截普通用户。

建议顺序：`API 真实连接测试` → `QQ-GATE-01 实机` → `第二环境（干净 Win11）` → `国内三层下载/离线闭包` → `代码签名 S1`。

## 6. 是否可以对外发布 0.2.0

**可以作为 0.2.0「技术预览（S0，未签名）」发布，但发布说明必须原文包含以下限制：**

1. QQ 机器人真实链路（扫码/收发/图片/重连/重启恢复）**未验证**，界面常驻 `QQ-GATE-01 未通过` 徽标；
2. 安装包**未做代码签名**，首次运行会出现"未知发布者"提示；
3. 仅在本机 **Windows 11 26200 非干净环境** + 历史 Windows 10 构建环境上验证，**干净机与第二环境未完成**；
4. DeepSeek API Key 只能本地加密保存，**不做真实连接测试**；
5. 诊断包已脱敏，但脱敏为模式驱动，导出前请人工确认预览。

**不得**以"QQ 完整可用"、"支持全部 Windows 10/11 干净机"等表述发布。

## 7. 一句话结论

M2 的**部署、任务控制、诊断导出、安装卸载与质量门禁**在本轮独立复核中全部实跑通过；但审计同时发现并修复了 **1 个可能删除用户 profile 的 P0 缺陷、2 个脱敏 P0/P1 缺陷、以及启动超时误判与版本信息错误**——因此 **M2 原始交付包不可直接发布，本报告对应的重建包（SHA-256 `08070338…306F6`）才具备技术预览条件**；QQ-GATE-01、API 真实连接、干净第二环境与代码签名仍未完成，不计入通过项。
