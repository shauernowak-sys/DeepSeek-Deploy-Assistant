# DeepSeek Deploy Assistant 开发说明

测试版 V0.1.1。给没有编程基础的 Windows 用户用：打开软件，点开始，装好 DeepSeek Harness，再接 QQ。

本仓库只做部署助手。Harness、SnowLuma、Aurabot 都是安装后的第三方程序，不在这里重写。

## 运行与打包

在仓库根目录：

```text
npm run dev          开发
npm run verify       类型检查、测试、许可证检查
npm run dist         打出未签名的 per-user 安装包
```

当前安装包：`release/test-v0.1.1/DeepSeek-Deploy-Assistant-Test-V0.1.1-x64.exe`  
83,726,559 字节，SHA-256 `3EB4D2FCB3CF25E596FC854DD9FED38532003181FEF1CB221EDBF8B0D87E0690`。  
FileVersion `0.1.1`。不需要管理员。`release/win-unpacked` 是打包中间目录，可以删掉再打。

打包前去掉环境变量 `ELECTRON_RUN_AS_NODE`。这个变量会让 Electron 变成 Node，窗口起不来。

## 代码在哪

| 目录 | 作用 |
|---|---|
| `apps/desktop` | Electron 主进程、预加载、界面 |
| `packages/core` | 部署、QQ、SnowLuma、插件目录 |
| `packages/adapters` | 下载、进程、Harness CLI、本机路径 |
| `packages/spec` | 版本基线、契约、门禁文案 |
| `catalog` | 插件资源中心条目 |
| `tests` | 自动化测试 |
| `apps/desktop/resources` | 随安装包发布的清单与图标 |

技术栈：Electron 33、React 18、TypeScript、electron-vite、Vitest、NSIS。

锁定基线：Node.js 22.23.4，pnpm 11.28.5，Harness `0.2.1-rc.3`（web profile），官方 QQ 插件 `@tencent-connect/dsh-qqbot@0.5.5`。数据在 `%LOCALAPPDATA%\DeepSeekDeployAssistant`。

## 用户怎么走

1. 选官方 QQ 或个人 QQ。
2. 部署向导安装私有 Node、pnpm 和 Harness。系统里已有可用的 Node 可以复用。
3. 配置 DeepSeek API。密钥只以 DPAPI 密文保存。
4. 插件资源里安装官方 QQ 插件或 Aurabot。
5. 个人 QQ：点「下载并安装 SnowLuma」。安装并启动成功后，把这份目录写进 Aurabot，用户不用再下载一次。扫码仍由用户本人完成。
6. 「启动并打开助手」会把最近和这个小号说过话的 QQ 接到当前对话。不用填写会话编号。
7. 打开助手时，如果 Aurabot 1.2.0 的向导第 4 步会把「下一步」卡住，软件会给已安装的插件补上三处：WebSocket 超过 8 秒就重试；登录号对上就能点下一步；测试连接后刷新页面。

## 不要打破的规则

- 已安装不等于可用。缺证据就写未验证。
- 日志和诊断里不能出现 API Key、令牌、密码。
- 不要声称完全离线，或所有下载都有国内镜像。
- 清理安装只删本次任务创建的路径，不删用户已有的 Harness profile。
- 进程只能用本软件带的 `node.exe` 启动。
- Aurabot 已经指向另一份能用的 SnowLuma 时，不要覆盖那个目录。

## 新电脑实测记录（2026-11-09）

这些是初代安装包在另一台电脑上碰到的问题。前几条已写进当前源码；最后两条不是「小号被旧电脑绑定所以不能用」。

1. **QQ 装在非默认目录时，下载前检查失败。** 界面上 QQ 已打开，但仍提示没有检测到桌面版 QQ（NTQQ）。原因是只查了三个固定路径。现已改为：正在运行的 `QQ.exe` 路径就算已安装。
2. **SnowLuma 安装包下到约 1% 就失败。** 报错是 `This operation was aborted`，随后同一个 GitHub 地址 `fetch failed`。原因是整段下载被 30 秒掐断，而且只有 GitHub 一个地址。现已改为：有数据继续传就不掐断；GitHub 失败后再试加速地址。文件仍必须对上清单里的 SHA-256。
3. **Aurabot 第 4 步已显示「连上了」，下一步仍是灰的。** 「测试连接」只说明 HTTP 通了，按钮却在等 WebSocket 核对通过。现已改为：连接超过 8 秒就重试；登录号对上就能点下一步；测试连接后刷新向导。
4. **Aurabot 第 2 步不认已经装好的 SnowLuma，还要求再下载。** 它只看自己的目录，默认是 `C:\Aurabot\snowluma`。现已改为：一键安装并启动成功后，把这份目录写进 Aurabot。
5. **个人 QQ 最后一步要用户填写助手会话编号。** 助手窗口里不显示这个编号。现已改为自动接到最近用过的对话，并接上最近和这个小号说过话的 QQ。
6. **SnowLuma 页面停在「等待登录」。** 右上角「已连接」只表示浏览器连上了控制台。紫色「等待登录」表示钩子已进入 `QQ.exe`，账号还没在 QQ 窗口里登录。扫码不在这个网页上。登录成功后再刷新，应变为「已在线」。
7. **旧电脑上绑定过的小号，不会锁住新电脑的 SnowLuma。** 那次绑定只在旧电脑的助手插件里。小号若仍在旧电脑的 QQ 里登着，新电脑的 QQ 可能登不进去，SnowLuma 就会一直停在「等待登录」。先在旧电脑退出这个小号，再在新电脑的 QQ 窗口扫码。
