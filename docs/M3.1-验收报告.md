## 2. 交付要求逐条回答

### 2.1 复用的官方能力及开源项目

**官方（Harness 0.2.0-rc.2，均经实测确认，未改源码）**：profile patch 配置层、`--dump-config` 组合自省、`--dump-config-schema` 字段自省、`apiKeyEnv` 凭据 seam 与启动环境优先级、`agent-default-model` 路由、`deepseek-official`（Messages 协议）与 `llm-pi-ai`（OpenAI 兼容）两条模型路由、官方模型目录（`deepseek-flash` / `deepseek-v4-pro`）。
**开源**：`js-yaml@4.1.0`（MIT，读写 patch）、既有 `resedit`（MIT）。许可证门禁通过（9 MIT + 1 Python-2.0，均在 allowlist）。

### 2.2 API 配置实现方式

在 `$DSH_HOME/profiles/web/cordis.patch.yml` 写入**带标记的受管块**（`llm-deepseek` 或 `llm-pi-ai` 路由 + `agent-default-model`），写前备份、写后用 `dsh --profile web --dump-config` 回读确认路由与默认模型真的生效；回读失败自动回滚。只改自己的块，用户其它条目与注释原样保留。

### 2.3 密钥安全方案

DPAPI 密文（`secrets.bin`）→ 启动 Harness 时作为 `apiKeyEnv` 对应环境变量注入 → Harness 官方凭据 seam 读取。
**磁盘上没有任何明文密钥**（单测逐文件扫描数据目录 + 实机校验）；渲染层只见掩码；日志与诊断包不留密钥；支持修改与删除（删除含二次确认）。

### 2.4 实际修改文件

**新增 5 个源码文件**（`packages/core/src/api/{types,harness-patch,connection-test,verify}.ts`、`apps/desktop/src/main/services/api-service.ts`）、**新增 5 个测试文件**、**修改 10 个文件**（core index、spec ipc、register、preload、main index、harness-service、adapters cli、secrets、App.tsx、package.json/lock），**新增 5 份文档 + 4 份证据**。详见 [实施报告 §2](./M3.1-实施报告.md#2-新增--修改文件)。

## 4. 结论

**M3.1 的功能实现与技术验证完成**：图形化 API 配置、DPAPI 密钥、真实连接测试与错误分类、配置写入与回读、失败回滚，均已在真实 Harness 0.2.0-rc.2 与真实端点验证；**并且已用用户真实 Key 得到 HTTP 200 与模型回复**（`verdict=ok`，767 ms，`deepseek-flash`）。

**唯一未完成的验收项**是"在 Harness Web 界面里人工发一条消息并收到回复"（1 分钟人工操作）。因此：

- 可以说：**API 配置与真实连接已打通**（真实 Key → 200 → 模型回复 → 配置被真实 Harness 采纳）。
- 谨慎表述：**"Harness 内对话可用"仍待人工确认一次**。

建议下一步：提供一次性有效 Key，按 [已知问题 K-M3-01](./M3.1-已知问题.md) 的三步复验（预计 10 分钟内完成）。

**验收期追加修复**：用户实机反馈"未部署就点启动 Harness 会报错"，定位到 `spawn` 失败未被监听导致主进程未捕获异常（弹出英文 JS 错误框），已修复并补 4 项回归测试、前置检查与中文指引（见 [K-M3-10](./M3.1-已知问题.md)、[m31-launch-preflight.log](./evidence/m31-launch-preflight.log)）。注意：**本软件不复用用户手动安装的官方 Harness**，它会在自己的数据目录部署隔离副本，所以必须先执行"一键部署"。

**真实环境复验（2026-11-03）**：静默安装 → 一键部署 13/13（58 秒）→ 真实 Key 连接测试 `verdict=ok`（767 ms）→ Harness 启动 `health=usable` → 部署根 `--dump-config` 含我们的 provider/model/apiKeyEnv。过程中又发现并修复一个真实缺陷：推理模型只回 `thinking` 块被误判为"响应格式异常"（[K-M3-11](./M3.1-已知问题.md)）。证据：[m31-real-key-acceptance.log](./evidence/m31-real-key-acceptance.log)。
