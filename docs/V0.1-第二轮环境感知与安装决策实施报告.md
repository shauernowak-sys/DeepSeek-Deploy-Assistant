**日期：** 2026-11-04

## 1. 本轮目标

让软件在**读取真实 Windows 环境**的基础上，判断下一步应当是安装、复用、升级、修复、阻止还是要求用户确认；并且把这一判断变成**部署执行器无法绕过的门禁**。

本轮不是给现有两态（已就绪/未安装）页面加几个按钮，而是补齐了从检测到执行的完整链路：

```
真实检测 → 五态判定 → 安装决策 → 风险评估 → 用户确认 → 执行部署
```

验收核心：**软件能否根据用户电脑的真实环境，安全、准确地决定下一步做什么**，而不是界面出现了多少状态。

## 2. 五态环境定义及 PRD 依据

冻结 PRD 没有单独定义"五态"枚举名，但在以下位置给出了原始定义，本轮**未创造任何新状态名**：

| 依据 | 原文 |
|---|---|
| `docs/PRD-V0.1-FROZEN.md` §7.1 | Node/pnpm：已安装且满足 / 已安装但版本过低 / 未安装 / 检测失败；Harness 见 §6.2 四态；网络：主源可用 / 仅镜像可用 / 均不可用 |
| `docs/03-开发任务拆分.md` B05 | "五态显示正确：已装 / 未装 / 版本不符 / 需升级 / 检测失败" |
| `docs/01-项目结构设计.md` ENV-001..003 | "每项显示 已安装 / 未安装 / 版本不符 / 需升级 / 检测失败 五态" |
| `docs/audit/V0.1-完整功能验收矩阵.md` ENV-5STATE | 同上，并要求统一 `ComponentState` |

实现（`packages/spec/src/environment.ts`）：

```ts
export const COMPONENT_STATES = [
  'installed',          // 已安装
  'missing',            // 未安装
  'version-mismatch',   // 版本不符
  'upgrade-required',   // 需升级
  'probe-failed',       // 检测失败
] as const;
```

补充约束：

- **检测失败 ≠ 未安装**：文件存在但无法执行、注册表读不到、注册表与目录矛盾，一律是 `probe-failed`，并在 `diagnosis` 中区分 `not-executable` / `ambiguous` / `probe-error`。
- **未知 ≠ 正常**：信号矛盾时 `route.kind = 'unknown'`，安装决策返回 `BLOCKED`。
- 非组件项严格使用 PRD §7.1 的独立枚举：OS（支持/不支持）、磁盘（充足/不足）、权限（普通用户/管理员）、网络（主源可用/仅镜像可用/均不可用）、目录（可写/不可写）。
- `upgrade-required` 只用于**本软件自己的私有组件**；用户已有的 Node/Harness 永远不会被标成"需升级"，因为本软件不升级用户环境。

## 3. 环境检测架构

### 3.1 分层

| 层 | 文件 | 职责 |
|---|---|---|
| 规格 | `packages/spec/src/environment.ts` | 五态、组件、前置项、决策、运行时选择类型 |
| 原始探测 | `packages/core/src/detect/probes.ts` | 纯数据结构；不包含任何默认假值 |
| 纯评估 | `packages/core/src/detect/evaluate.ts` | 原始值 → 五态报告；可单测、无 IO |
| 真实探针 | `packages/adapters/src/detect/system.ts` | 读取 PATH、常见安装目录、注册表、网络、磁盘、权限 |
| 决策 | `packages/core/src/decide/installation.ts` | 六种内部动作；纯函数 |
| 门禁 | `apps/desktop/src/main/services/env-service.ts` | 扫描序号、planId、有效期、确认校验 |
| 执行 | `deploy-service.ts` / `deploy-plan.ts` | 仅接受门禁返回的 `RuntimeSelection` |

### 3.2 真实数据源

| 对象 | 数据源 |
|---|---|
| 系统 Node | `PATH` 逐项查找 + `%ProgramFiles%`、`%LOCALAPPDATA%\Programs\nodejs`、`nvm`、`fnm_multishells`、`Volta`、`Scoop`；逐个执行 `node.exe -v` |
| PATH 实际命中 | 记录 `onPathOrder`，并单独给出 `resolution.pathNode` |
| 多版本 | 所有候选去重后保留，不只看 PATH 第一个 |
| 路径稳定性（D-6 ③） | `nvm` / `fnm_multishells` / `Volta` / `Scoop apps` / `Temp` 判为不稳定，默认不复用 |
| 可执行性（D-6 ②） | 真正执行 `node.exe -v`；失败即 `probe-failed` |
| 写权限（D-6 ④） | 只读取/执行 Node，不要求写入 Node 目录；检测阶段不创建任何目录 |
| 私有 Node/pnpm/Harness | 本软件数据目录中的真实文件 + 真实执行 `-v` / `--version` |
| 系统 Harness CLI | `PATH` + `%APPDATA%\npm` + `%LOCALAPPDATA%\pnpm` 中的 `dsh.cmd/.exe/.ps1`；从 `.cmd` shim 解析 JS 入口后用 `node.exe <bin.js> --version` 读取版本 |
| Harness Desktop | HKCU 卸载注册表 `DisplayName = "DeepSeek Harness"` + 安装目录主程序；读不到注册表记为 `probe-failed`，不是 `missing` |
| Profile | `<DSH_HOME>/profiles`、`profiles/web`、`profiles/desktop` 的真实存在性 |
| 网络 | 清单主源 URL + registry ping + 全部备用镜像；HEAD/GET Range，5 秒超时 |
| 磁盘 | 数据目录所在盘符（不再硬编码 `C:\`） |
| 权限 | SAM 读取判管理员（信息项，本软件不需要管理员）；数据目录最近存在祖先的 `W_OK` |
| 时间 | 每个组件与整份报告都有 `checkedAt`；报告有唯一 `scanId` |

### 3.3 只读与超时

- 检测过程**不创建目录、不安装、不改 PATH/环境变量/注册表**。
- 真实 Windows 集成测试额外断言：对空数据目录执行检测后，目录仍不存在。
- 所有命令都有超时（Node 8s、pnpm/Harness 20s、reg 20s、网络 5s）。
- 单个探针失败只写入 `probeErrors`，不会把其它组件判成"未安装"。
- 网络失败只影响网络前置项，不影响本地组件结论。

### 3.4 未纳入的检测项及理由

| 项 | 结论 | 理由 |
|---|---|---|
| Git | 不检测 | PRD §19 明确 V0.1 不做 Python/FFmpeg/Git 适配；当前部署只从 registry 安装包，不依赖 git |
| 端口占用 | 不检测 | 本软件启动 Harness 使用 `port 0`（系统自动分配），端口占用不构成部署前置；PRD §7.1 未把端口列入环境检测 |
| Python / FFmpeg | 不检测 | 不在 V0.1 范围（§19） |
| 内存 | 不检测 | PRD 五态/验收未要求；不为了增加检测项而引入无关依赖 |

## 4. 安装决策规则

内部动作（`DECISION_ACTIONS`，不是环境状态）：

| 动作 | 含义 |
|---|---|
| `INSTALL` | 需要安装（私有运行时或隔离副本） |
| `REUSE` | 可复用，不重复安装 |
| `UPGRADE` | 本软件自己的组件需要升级/替换 |
| `REPAIR` | 本软件自己的组件损坏，需要修复 |
| `BLOCKED` | 禁止继续 |
| `CONFIRM_REQUIRED` | 需要用户选择/确认 |

优先级：`BLOCKED > CONFIRM_REQUIRED > REPAIR > UPGRADE > INSTALL > REUSE`。

### 4.1 场景覆盖

| 场景 | 判定 |
|---|---|
| A 全新环境 | Node/pnpm/Harness 全部 `INSTALL`；`requiresNetwork=true`；安装顺序仍为 Node → pnpm → Harness → profile → 插件 |
| B 已有满足要求的 Node | 单个稳定候选 → `REUSE`；部署计划**移除**下载/解压步骤，pnpm/Harness 用系统 `node.exe` 执行；不改系统 Node |
| C 已有 Harness | 版本一致且可执行 → `REUSE`；版本不同 → 安装**隔离副本**，不覆盖用户安装；多位置 → `CONFIRM_REQUIRED` |
| D CLI + Desktop 并存 | `CONFIRM_REQUIRED`；确认后只使用 `web` profile，Desktop 与 `desktop profile` 保持不修改 |
| E 多版本 | 多个稳定 Node → 每个版本一个选项 + "使用私有运行时"；多个 Harness → 每个位置一个选项 + 私有安装；用户必须显式选择 |
| F 环境损坏 | 文件不存在→`missing`；存在但不可执行→`probe-failed`；版本低→`version-mismatch`；本软件私有组件损坏→`REPAIR`；权限/网络异常→对应前置项；每种都有不同处理 |
| G 无法确认 | 路线 `unknown` → `BLOCKED`；注册表/目录矛盾 → `probe-failed`；未完成探针不会被当作正常 |

### 4.2 每个决策必须回答的 9 个问题

`ComponentDecision` / `InstallationDecision` 已包含：

1. 当前环境（component/state/current version+path）
2. 检测证据（`evidence[]`，原始值）
3. 推荐操作（action）
4. 操作原因（reason）
5. 可能影响的用户数据（impacts；空数组表示只读）
6. 是否需要管理员（恒为 false，除非阻塞）
7. 是否需要联网（仅 INSTALL/UPGRADE/REPAIR）
8. 是否需要用户确认（所有部署都需要）
9. 失败后的恢复策略（recovery）

确认页另外给出：安装清单、复用清单、修改清单、**不会修改清单**、安装位置、预计占用、网络需求、实际运行时。

## 5. 安全门禁

### 5.1 执行链路

```
renderer
  └─ env:inspect → EnvironmentReport + InstallationDecision(planId)
  └─ env:decide  → 用户选择后重新决策（新 planId）
  └─ task:start { planId, confirmed:true }
         └─ EnvService.authorize(planId, confirmed)
                ├─ 未确认 → E_DECISION_UNCONFIRMED
                ├─ planId 不存在 → E_DECISION_REQUIRED
                ├─ 已过期 / 被新检测取代 → E_DECISION_STALE
                ├─ BLOCKED / 仍需选择 → E_DECISION_BLOCKED
                └─ desktop profile 不可写 → E_PROFILE_OWNED_BY_DESKTOP
         └─ 只有通过后才写 runtime-selection.json 并启动执行器
```

- `task:start` 的 zod schema **强制要求** `planId`（≥8 字符）与 `confirmed`；旧调用方式直接解析失败。
- `task:resume` 只允许继续**已存在任务记录**的任务；没有记录时拒绝（`E_DECISION_REQUIRED`），不存在绕过门禁的第二个入口。
- 执行器使用门禁返回的 `RuntimeSelection`，不能自行改回私有/系统路径。
- 决策有效期 10 分钟；任何一次新的检测都会使旧 planId 失效。
- 并发检测：后发起的检测是唯一事实源；先发起但后完成的结果会复用较新的环境快照，不会互相覆盖。
- `isWritableProfile` 已在门禁层接线；`desktop` profile 永远拒绝写入。

### 5.2 禁止事项核对

| 禁止项 | 实现 |
|---|---|
| 自动删除系统 Node | 从不调用删除；系统 Node 只读复用 |
| 覆盖用户已有 Harness 配置 | 版本不一致时安装到本软件目录；系统 Harness 仅读调用 |
| 未经确认修改 PATH/系统环境变量 | 仅对子进程注入 PATH；不写系统环境变量 |
| 未经确认删除已有 Profile | `dsh-home` 不进入 `created[]`；取消/回滚不删 profile |
| 清理无法确认归属的目录 | 只删本任务记录的、位于管理根目录内的路径（沿用第一轮能力） |
| 版本不匹配就直接覆盖 | 用户 Harness 只装隔离副本；本软件组件降级需确认 |
| 未确认就执行 | `confirmed:false` 直接拒绝，测试验证不会创建任务记录 |
| 取消后继续执行 | 确认弹窗取消仅关闭界面，不调用 `task:start`；UI 冒烟验证任务记录未变化 |

## 6. UI 变化

保持既有工业监控风格，不进行全局改版。

### 6.1 环境总览

- 结论徽标：需要安装 / 可以复用 / 需要升级 / 需要修复 / 禁止继续 / 需要你确认。
- 六个组件行：系统 Node、私有 Node、pnpm、私有 Harness、系统 Harness、Harness Desktop。
- 每行显示五态徽标 + 实际版本 + 版本要求。
- OS / 磁盘 / 权限 / 网络 / 目录以状态徽标列出。
- 明确写"这一步只读，不会修改你的电脑，也不会安装任何软件"。

### 6.2 检测详情

折叠区显示：实际版本、安装路径、检测时间、异常原因、所有候选路径与原始证据；探针失败单独列出，不与"未安装"混在一起。

### 6.3 安装建议

只列出需要处理（非 REUSE）的组件，并给出一句原因；全部满足时明确显示"无需安装或修改本软件自己的组件"。

### 6.4 操作确认

确认弹窗回答：

- 本次会安装什么
- 本次会复用什么
- 本次会修改什么
- 本次不会修改什么（系统 Node / PATH / Desktop / desktop profile / 用户 Harness / 数据目录外文件）
- 安装位置与预计占用
- 是否需要管理员（不需要）
- 是否需要联网
- 实际使用的 Node / Harness 模式
- 失败后如何恢复

多版本/路线并存时先进入"选择方案"，每个选项说明路径与影响，用户选择后才进入最终确认。

## 10. 已知问题

1. **系统 Harness 复用受 shim 形式限制**：能从 `dsh.cmd` 解析出 JS 入口时才能读取版本并复用；只有 `dsh.exe` 时无法进入安全执行白名单，会显示"检测失败"，决策回退为安装隔离副本（安全，但会多占空间）。
2. **多版本 Node 默认不复用**，必须用户显式选择；这与 PRD D-6"路径稳定"一致，但会增加一次交互。
3. **安装体积/时间是估算值**（约 150–350 MB、几分钟），不是按包精确计算。
4. **网络检测依赖外部源**：企业代理/离线环境可能显示"均不可用"；纯复用场景不会因此阻塞。
5. **启动时自动检测会发起网络探测**（最长约 5 秒，后台执行，不阻塞首屏）。
6. **`env:scan` 已移除**，只保留 `env:inspect` / `env:decide`；旧脚本/文档若仍调用 `env:scan` 会失败。
7. **确认页是模态弹窗**，不是 PRD §21.4 的独立向导页；内容要素已覆盖，分步向导骨架仍未实现。
8. **私有运行时只检测锁定版本路径**（`runtimes/node/22.23.4`）；更早版本残留目录不会被枚举。
9. **检测的可写性判断**使用最近存在祖先的 `W_OK`，不覆盖长路径/组策略/ACL 边缘情况。
10. **并发检测**由 `EnvService` 序号保证，并用单元测试模拟并发完成顺序；未用两个真实 IPC 客户端压测。
11. **`node:fs`/注册表探测在非 Windows 平台会失败**，报告为 `probe-failed` + OS 不支持；V0.1 只支持 Windows。
