## 1. 「重试这一步」为什么不能直接用 `resume`

`resume` 已经能"从失败的那一步继续"，但它会**一路跑到底**。对下载/安装这类耗时长、可能改动 profile 的步骤，用户想先看这一步到底成不成、再决定是否往下走。

所以这里实现的是**语义不同**的两个入口：

| 入口 | 行为 | 用途 |
|---|---|---|
| 「重试失败步骤」（`task:resume`） | 从卡住的步骤继续，直到结束 | 已经确认环境没问题，想一次装完 |
| 「重试这一步」（`task:retry-step`，本次新增） | **只重跑这一步**，成功后停下（`paused`），后续步骤保持 `pending` | 想先验证这一步、再决定是否继续 |

### 1.1 引擎改动（`packages/core/src/engine/executor.ts`）

- 新增 `ExecuteOptions.stopAfterStepId`：该步骤 `succeeded` 或 `skipped` 后立即 `finish('paused', …)`，后续步骤不动。
- 新增 `pausedReason: 'user' | 'step-retry'`（`TaskSummary` / `JournalData` / `Journal.toSummary` 同步）：
  **不能复用 `pausedByUser=true`**——那会把"重试成功停在半路"说成"你主动暂停了"，正是 Q-EXEC 修过的老毛病。UI 据此显示不同文案。

### 1.2 服务端守卫（`DeployService.retryStep`）

拒绝而不是猜测，四种情况都拒绝并给出可执行提示：

1. 任务 ID 不匹配；
2. 任务正在运行（不能同时重试某一步）；
3. 所有步骤都已完成（提示改用「重新部署（修复）」）；
4. `stepId` 不是"第一个未完成的步骤"→ 消息里点名当前真正卡住的步骤。

守卫拒绝时 **journal 一个字节都不改**（有用例断言）。

### 1.3 接线

| 层 | 改动 |
|---|---|
| 契约 | `TaskRetryStepSchema { taskId, stepId }`（strict） |
| IPC | `task:retry-step` |
| preload | `retryStep(taskId, stepId)` |
| 渲染层 | 失败步骤行下新增「重试这一步」按钮；暂停横幅按 `pausedReason` 分文案；失败横幅说明两种重试的区别 |

### 1.4 测试

- `tests/core/executor-retry-step.test.ts`（4 例）：只跑目标步且停下、`pausedReason=step-retry`、已完成的步骤不重跑、停下后「继续」能跑完剩余、目标步被 `precondition` 跳过时也停、不传该参数行为不变。
- `tests/desktop/deploy-service-retry-step.test.ts`（5 例）：四个守卫 + 拒绝时不改 journal。
- `tests/desktop/ipc-contract.test.ts` 继续守护"主进程 handler ↔ preload ↔ 渲染层调用"三端一致（新增通道若有一端漏接，测试直接失败）。

## 2. 双分辨率视觉验收

### 2.1 方法

`scripts/m4-recovery-ui-smoke.mjs`（CDP 直连，复用既有 `v01-*` 冒烟脚本的做法），要点：

- **隔离数据目录**：应用以 `LOCALAPPDATA=%TEMP%\dda-ui-smoke` 启动，并预置两个 fixture：
  - 一份 `state/backups/plugin-*`（4 个声明文件）→ 弹窗显示真实备份列表而不是空态；
  - 一份 `state/tasks/full-deploy-0_2_0-rc_2.json`（含 1 个失败步骤）→ 部署页出现「重试这一步」。
  - 另补一个空的 `runtimes/pnpm/node_modules/pnpm/bin/pnpm.cjs`，让"pnpm 可用"分支被覆盖（否则弹窗只会显示"没有可用的 pnpm"）。
- **视口用 `Emulation.setDeviceMetricsOverride`**（1920×1080、1366×768，DPR=1）。这是视口模拟，不是物理窗口尺寸，报告里如实写明。
- **硬断言**（任一不满足即失败，不靠"截图看着还行"）：
  - 弹窗文案含影响面（4 个声明文件 / 恢复前自动备份 / 确认恢复）；
  - 有备份时必须展示重建命令或明确说明缺 pnpm；
  - 两种分辨率下 `document.scrollWidth ≤ innerWidth + 1`（无横向溢出）、弹窗左右边界在视口内、按钮存在且可用；
  - 取消后弹窗关闭；
  - 失败步骤上的「重试这一步」**可见可点**（只检查存在性，不点击——点了会真的重跑部署）。
