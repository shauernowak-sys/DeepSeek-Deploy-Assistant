## 5. 双路线抽象现状（为什么不能"加一个配置页"就完事）

| 层 | 现状 | 个人 QQ 需要的改动 |
|---|---|---|
| `packages/spec` | 只有 `QqStatus`（隐含"官方 bot"语义）、`QqSettings`、`QqCredentials` | 新增 `QqRoute = 'official' \| 'personal'`、`PersonalQqComponent` 注册表类型、`PersonalQqStatus`（安装/运行/联通 三段证据）、`PersonalQqDetection` |
| `packages/core` | 只有 `qq/{patch,status,version}`，全部围绕 `im-qqbot` | 新增 `qq/personal/{registry,license,detect,guide}.ts`；`status.ts` 需按 route 分流 |
| 主进程 | `QqService` 单例，只服务官方 bot | 新增 `PersonalQqService`（探测/引导/状态），**不复用** `QqService` 的凭据与受管块（配置隔离，防误删） |
| IPC | `qq:*` 14 个通道，无 route 参数 | 新增 `qq:route`、`personal:*`（探测、打开官方入口、保存组件选择），并对 `qq:*` 明确"只作用于官方路线" |
| 渲染层 | 单一 Section 4「QQ 机器人（官方插件）」 | 新增「QQ 接入中心」（两张卡片 + 路线选择），官方区块下沉为子页；个人区块含可行性矩阵、引导步骤、检测结果 |
| 安全 | `Secrets`（DPAPI）只存官方凭据 | 第三方组件凭据**不假定**受 DPAPI 保护；只记录"凭据存放位置/是否明文"的事实，不代管 |

**判定**：这不是"给官方 QQ 加一个 tab"，必须新增独立服务的边界，否则必然出现"一条路线的状态/卸载影响另一条"（任务书 §5.1 明令禁止）。
