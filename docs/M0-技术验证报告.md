## 4. T3 ★ C1 组合：`dsh@0.1.0-rc.8` + `dsh-qqbot@0.5.5` + Node 22.23.4 → **失败**

**步骤**
1. `dsh --version` → `0.1.0-rc.8`（通过）
2. `dsh plugin --profile dda-core add @tencent-connect/dsh-qqbot@0.5.5` → 成功（7.4 s，37 包）
3. `dsh plugin --profile web add …` → 成功（web 自带 `dsh-web-app` bundle）
4. `dsh --profile web --no-open --port 0` → **崩溃**

**错误（3 次复现，含 1 次全新 `DSH_HOME` 且未装任何插件）**

```
dsh web: http://127.0.0.1:58028
Error: dsh: user patch-layer watching requires the Cordis HMR service
    at watchUserPatches (.../@deepseek-ai/dsh-app-boot/lib/index.js:764:28)
    at runProfile (.../@deepseek-ai/dsh/lib/profile-boot-DG5t9aNs.js:264:9)
Node.js v22.23.4   → exit 1（约 2 s 内）
```

| 指标 | 实测 |
|---|---|
| 失败复现率 | 3/3（其中 1 次为全新 home、零插件） |
| 失败耗时 | 约 2 s（打印 URL 之后立即抛错） |
| stderr 其他错误 | 无（仅此一条） |

**已排除的原因**（逐项核查）

| 假设 | 证据 | 结论 |
|---|---|---|
| 包缺失 | `profiles/node_modules/@deepseek-ai/cordis-plugin-hmr` 存在（junction 指向 `.pnpm`），版本 1.0.20 | 排除 |
| 模块无法 import | 在 `profiles` 目录下 `import('@deepseek-ai/cordis-plugin-hmr')` → OK；timer / cordis 亦 OK | 排除 |
| peer 版本不满足 | hmr 要求 `cordis ~4.0.5`、`timer ~1.1.7`；实际 cordis 4.0.5、timer 1.1.7 | 排除 |
| 插件导致 | 全新 home、未装插件同样失败 | 排除 |
| 本机环境问题 | 同一 Node、同一机器，`0.2.0-rc.2` 启动成功（见 T4） | **排除** |
| 根因 | 尚未定论：疑似该版本 `runProfile` 在动态加载 HMR 后读取 `ctx.get('hmr')` 的时序缺陷，或 0.1.0-rc.8 的 web bundle 未挂载 HMR 服务 | **未定论** |

**判定：C1 失败。** 证据：`logs/08-boot-web.log`、`logs/09-boot-web-retry1.log`、`logs/10-boot-web-retry2.log`、`logs/11-fresh-web-{out,err}.log`

> 与上游声明冲突：`dsh-qqbot@0.5.5` 元数据称 `0.1.0-rc.8` 为"CLI（`dsh web`）已验证"。本机（Win10 19045 + Node 22.23.4 + pnpm 11.28.5 + 全新 home）**不可复现该结论**。不排除上游是在不同 OS/Node/安装方式下验证。

## 6. T5 是否重复安装 `dsh-llm`

**方法**：解析 profile 的 `node_modules`、`pnpm-workspace.yaml`、`package.json`、`pnpm-lock.yaml`。

**结果**

| 证据 | 内容 |
|---|---|
| `profiles/web/pnpm-workspace.yaml` | `nodeLinker: hoisted`、**`autoInstallPeers: false`** |
| `profiles/web/package.json` | 依赖只有 `@tencent-connect/dsh-qqbot: 0.5.5`；`dsh.profile.bundles = [dsh-base, dsh-web-app, dsh-qqbot]` |
| profile 内 `@deepseek-ai/*` 包 | **0 个**（`dsh-llm`、`dsh-session` 等均未安装） |
| 宿主提供的版本 | `dsh-base@0.2.0-rc.2` 依赖 `@deepseek-ai/dsh-llm@^0.2.0-rc.2`，由宿主树提供 |
| 运行时表现 | 插件启动无报错（stderr 0 行） |

**判定：不重复安装。** 结论：`autoInstallPeers: false` + 宿主 runtime resolution 共同保证 peer 由宿主提供；**原先"0.2 宿主会解析到 0.1.x 旧线"的机制性担忧，在本安装方式下不成立**（peer 根本不会被安装）。

**设计影响**：profil 内的 peer 缺失是**预期行为**，UI 不得以 `pnpm peers check` 的 warning 判定插件损坏；判定必须基于运行时证据（插件是否注册、是否进入扫码/心跳）。

### 16.4 仍存在的技术风险

1. **0.1.0-rc.8 与上游"已验证"声明不一致** → 兼容矩阵不能照抄上游元数据，必须以本机复现为准。
2. **`dsh web` 需要 token**，无 token 一律 401 → 健康探测、进程存活判定、端口探测的规则都要按 401 设计，否则会误报"服务未就绪"。
3. **只测了 1 台 Win10、1 条网络**：Win11、电信/移动双网、代理环境均未覆盖。
4. **真实 QQ 收发未测**：这是 Gate 3 的核心，无法用任何替代手段证明。
5. **pnpm `ERR_PNPM_IGNORED_BUILDS`**：`node-pty` 等原生模块的 postinstall 被拦截，当前 web 启动未受影响，但终端/PTY 相关功能未验证。
6. **插件安装写用户级 pnpm store**：与"只删自己创建的文件"边界存在张力。
7. **0.2.x 依赖体积翻倍**（194 MB → 452 MB），下载与磁盘占用需重新评估。

## 17. 对文档的修订建议（不擅自改定位）

1. **C1 组合作废，改为 C1′**：`dsh@0.2.0-rc.2 + dsh-qqbot@0.5.5 + Node@22.23.4`（状态：`verified-local`，待第二台机器复现）。
2. **安装工具固定为 pnpm**（dsh 自带 profile 安装器本身就用 pnpm）；npm 不作为 fallback。
3. **健康探测规则**：`GET /` 返回 **401 视为在线**；带 token 返回 303 视为可用。
4. **peer 缺失不是错误**：profile 明确 `autoInstallPeers: false`，不得据此判失败。
5. **主动互动降级**：V0.1 的"主动互动"只能标注"默认不可用/待挂载验证"。
6. **许可门禁**：允许清单需加入 `Python-2.0`（附理由）或强制 allowlist；同时新增"元数据缺失时读取 tarball LICENSE"。
7. **profile 命名**：0.1.x 无 `--from-default-profile`，且自定义名 profile 只含 `dsh-base`（无 Web UI）→ **必须安装进 `web` profile** 才能得到 Web UI；"使用专有名 profile"的旧设计不成立。
