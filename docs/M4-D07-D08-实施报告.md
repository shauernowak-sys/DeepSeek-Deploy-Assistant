## 1. D07 版本决策（[packages/core/src/market/version-plan.ts](../packages/core/src/market/version-plan.ts)）

| 输入 | 结果 |
|---|---|
| 未安装 | `install`，`method=add`，做 compat 断言并给出 `comboId` |
| `installed === target` | `none`，**不进入编排、不发起 pnpm** |
| `target > installed` | `upgrade`，`method=remove-then-add`；组合必须 `verified-local`，否则第 1 步拒绝 |
| `target < installed` 且未确认 | 抛 `E_DECISION_UNCONFIRMED`，消息含"当前 X → 目标 Y" |
| `target < installed` 且已确认 | `downgrade`，`requiresConfirmation=true`，warnings 含降级提示 |
| 目标包名与已安装不同 | 拒绝（一次只切换一个插件） |

补充：

- `assertCombo: false` 供安装编排使用——兼容门禁统一由**第 1 步**执行，错误消息始终带步号（`第 1 步（compat）失败：…`），不会出现两套口径。
- 切换警告固定两条："会先卸载再安装（锁定宿主不支持原地升级），profile 依赖会被重建""切换前会自动备份 profile"。

安装编排（[install-plan.ts](../packages/core/src/market/install-plan.ts)）的接入点：

- 同版本 → 直接返回 `action: 'none'`，`steps: []`，日志"同版本不再重复安装"；
- 切换 → 缺 `backupProfile`/`removePlugin` 时**拒绝执行**（不允许无备份 remove+add）；
- 第 5 步内顺序固定：**备份 → 卸载 → 安装**，且备份与卸载各只执行一次（该步重试不会重复）。

## 2. D08 备份与恢复（[packages/core/src/market/profile-backup.ts](../packages/core/src/market/profile-backup.ts)）

| 项 | 实现 |
|---|---|
| 备份对象 | `package.json`、`pnpm-workspace.yaml`、`cordis.patch.yml`、`pnpm-lock.yaml`（存在才备份，缺失记入 `missing`） |
| 备份位置 | `<root>/state/backups/plugin-<ISO 时间>/`（`AppPaths.stateBackups`） |
| 保留策略 | 最近 3 份（与 API 配置备份一致） |
| 未初始化 profile | 缺 `package.json` → 拒绝，不生成空备份 |
| desktop profile | 备份与恢复都拒绝（`E_PROFILE_OWNED_BY_DESKTOP`） |
| 恢复 | 先把备份与当前文件读入内存；逐个 `写临时文件 → rename`；任一失败按内存快照回滚，抛 `E_ROLLBACK_FAILED` |
| profile 中同名路径是目录 | 在写入前拒绝（`E_MANIFEST_INVALID`），不改任何文件 |
| 重建依赖 | 恢复结果返回 `rebuildArgs = ['install','--offline','--frozen-lockfile','--force']` |

### 2.1 关于 `--force` 的实测依据

真实链路第一次尝试用普通 `pnpm install --offline --frozen-lockfile` 重建，pnpm 回答 `Already up to date`，而 `node_modules/@tencent-connect/dsh-qqbot` 仍然不存在（`dsh plugin list` 随后报 `cannot resolve profile bundle`）。加 `--force` 后 866 ms 重建完成。因此：

- `--force` 不是"更保险"，而是**恢复后唯一能生效的方式**；
- 该参数由 `restoreProfileBackup()` 的返回值携带，桌面侧 `HarnessService.restoreProfile()` 直接用它。

### 2.2 桌面侧接线

`HarnessService.restoreProfile(backupDir)`（[harness-service.ts](../apps/desktop/src/main/services/harness-service.ts)）：

1. `restoreProfileBackup()` 文件级还原；
2. 用私有/复用 Node 执行 `pnpm <rebuildArgs>`（目录为 profile，env 沿用 `dshEnv`，含 P-11 的代理剔除）；
3. 返回还原的文件清单与 `listPlugins()` 结果。

UI 入口留待 D02；本批只保证能力与证据存在，不新增死 IPC 通道。

## 3. 验收对照

| 原始验收标准 | 证据 |
|---|---|
| 同版本不重复装 | `install-plan` 单测：`action='none'`、`addPlugin` 未被调用、`steps=[]` |
| 降级有二次确认 | `version-plan` 单测：未确认抛 `E_DECISION_UNCONFIRMED` 且消息含"当前→目标"；已确认才返回 `downgrade` |
| 升级只在白名单组合内 | `version-plan` 单测：未验证组合直接拒绝；编排里第 1 步同样拦截 |
| 回滚后 `listPlugins` 与备份前一致 | **真实链路 E2E：PASS**（见 evidence 日志） |
| reset 前已生成备份且二次确认 | 编排强制 `backupProfile`：缺能力时拒绝 remove+add；备份先于卸载 |
| 恢复不触碰 `desktop` profile | 备份/恢复两处都拒绝，单测覆盖 |
