## 3. 功能实现说明

### 3.1 任务控制

- **暂停**：在步骤边界生效（协作式）。正在执行的步骤不会被强杀，避免 pnpm 写入中途被斩断导致 profile 半损坏。`暂停` 后 journal `status=paused`、`pausedByUser=true`，UI 显示"已暂停"。
- **继续**：`start()` 复用同一 journal，`succeeded` / `skipped` 的步骤不重跑。
- **取消**：`AbortSignal` 传到下载器与步骤上下文；当前步骤结束后执行器返回 `cancelled`。
- **取消确认**：弹窗列出**本次任务 journal `created[]` 里的全部路径**，并显示其中"当前存在"的数量；用户可取消整个取消动作。
- **清理边界**：只删除 journal 记录的本任务创建路径；删除后回收因此变空的父目录，但**绝不越过安装根目录**（`rollbackPlan(..., root)`）。
- **保留项**：`cache/pnpm-store`、`dsh-home`（用户 profile）、`state`、`logs` 不删；UI 明确提示"下载与包缓存会保留，以便下次安装更快"。

### 3.2 诊断报告导出

- 两阶段：先 `diag:preview` 返回 7 段清单与字节数（**预览内容已脱敏**），用户确认后才 `diag:export` 落盘；用户可以取消。
- 7 段固定内容：`01-system`、`02-runtime`、`03-profile`（只列目录结构，不含文件内容）、`04-plugins.json`、`05-task.json`、`06-network`、`07-logs`（最多 3 个文件，各取末尾 32 KB）。
- 脱敏在**构建阶段**完成（`sanitize()`），不是导出时补救：API Key / `QQBOT_SECRET` / `appSecret` / `appId` / 长 token / 用户主目录 / 长数字串统一替换为 `<redacted>` 或 `<user>`。
- 全程不经我方服务器。

### 3.4 稳定性修复（本轮实测发现的两个真实缺陷）

1. **Journal 原子写入在 Windows 上会 `EPERM`**：目标文件被并发读取（驱动轮询 / 杀软 / UI 刷新）时 `rename` 失败，异常逃逸后任务永远停在 `running`。修复：`EPERM/EACCES/EBUSY/EEXIST` 退避重试 6 次；`DeployService.start()` 增加 `.catch(failUnexpected)`，把异常写进 journal 并通知 UI。
2. **取消后残留空目录**：`created[]` 只记录叶子路径，父目录（如 `runtimes\node`、`harness`）被留在磁盘上。修复：清理后自底向上回收空父目录，边界为安装根目录；并补充单元测试（用户数据目录不受影响）。

### 3.5 质量门禁

- `npm run verify` = `typecheck` + `vitest run` + `license:check`，**60 通过 / 2 跳过**（2 个集成测试默认按环境变量门控，未删除、未降级）。
- `license:check`：解析生产依赖闭包 8 个包，全部 MIT；对元数据缺 `license` 的包回退读取 tarball 内 LICENSE（`qrcode-terminal` 属此类）。存在 `UNLICENSED` 时门禁失败。
- `DDA_E2E=1` 时额外跑真实集成测试（完整部署、幂等重跑、`dsh web` 健康到 `usable`）。

## 4. 关键设计决策（避免后续被误改）

| 决策 | 理由 |
|---|---|
| 取消是协作式，不强杀子进程 | 强杀 pnpm 会留下半写入的 `node_modules`，下次安装不可预测；协作式最多多等一个步骤 |
| 清理只信 journal `created[]` | 用户既有 Harness / profile / API 配置绝不在清单里，物理上不可能被误删 |
| 缓存保留 | `cache/pnpm-store` 不是"安装产物"而是可再生的加速缓存；删掉只会让用户下次更慢 |
| 诊断脱敏前置到构建阶段 | 预览阶段就必须安全，否则"预览"本身就是泄漏面 |
| 修复重跑用 `fresh` 归档旧 journal | 已成功任务的 journal 会让引擎判定"无需重跑"，用户点"修复"却无动作属于欺骗性 UI |
| 零依赖 ZIP 写入（STORE） | 诊断包体积小（~14 KB），引入压缩库只为省几 KB 不值得扩大供应链 |
