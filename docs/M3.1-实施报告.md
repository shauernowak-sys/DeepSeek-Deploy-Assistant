## 1. 端到端流程（已实现）

```
用户填写（服务类型 / 名称 / 接口地址 / 模型 / API Key）
   ↓ 本地校验（不联网；地址、模型、名称、凭据名）
   ↓ 密钥写入 DPAPI（secrets.bin，密文）
   ↓ 写入 Harness 配置：$DSH_HOME/profiles/web/cordis.patch.yml 的受管块（先备份）
   ↓ 回读校验：dsh --profile web --dump-config → 解析组合树，确认路由与默认模型
   ↓ 真实连接测试：一次最小请求（按协议）+ 错误分类
   ↓ 展示结果（成功/失败分类/下一步）
```

保存与测试是**两个独立动作**：可以先"测试连接"（用表单里的值，不落盘），满意后再"保存并应用"。

## 3. 配置写入方式（CFG-1..CFG-5 对照）

写入的是 `$DSH_HOME/profiles/web/cordis.patch.yml` 里一个**带标记的受管块**：

```yaml
# >>> dda:managed:begin  (DeepSeek Deploy Assistant 写入，请勿手工修改)
- id: llm-deepseek
  config:
    apiKeyEnv: DEEPSEEK_API_KEY
    baseURL: https://api.deepseek.com/anthropic
- id: agent-default-model
  config:
    provider: deepseek-official
    model: deepseek-flash
# <<< dda:managed:end
```

自定义 OpenAI 兼容服务则写 `llm-pi-ai.providers.dda-custom`（`api: openai-completions`、`baseURL`、`apiKeyEnv`、`models[]`）并把 `agent-default-model` 指到该路由。

| 约束 | 落实 |
|---|---|
| CFG-1 只用官方文档化途径 | profile 的 patch 层（文件首行注释即官方说明；settings UI 也写这里） |
| CFG-2 字段/层级/生效/回读必须实测 | 字段来自 `--dump-config-schema`；生效与回读用 `--dump-config` 实测（含"同 id 后写者生效"实验） |
| CFG-3 未验证前不写 | 已验证后才写；Harness 未安装时只保存本地配置并明确提示"部署后生效" |
| CFG-4 先备份、可回滚、不动其它项 | 写前 `.dda-backup-<时间戳>`；只增删自己的受管块；回读失败自动回滚 |
| CFG-5 不改数据库/二进制 | 未使用任何非文件途径 |

## 4. 密钥安全方案

| 环节 | 做法 |
|---|---|
| 存储 | DPAPI（`safeStorage`）密文写入 `%LOCALAPPDATA%\DeepSeekDeployAssistant\secrets.bin`；无明文文件 |
| 渲染层 | 只能拿到掩码 `sk-****abcd`；输入框留空表示"不修改" |
| 交付给 Harness | 启动 `dsh web` 时把它作为 `apiKeyEnv` 指定的**环境变量**注入（官方文档化的凭据 seam，优先级最高且只读） |
| 日志 | 沿用 M2.1 的字段名驱动脱敏；连接测试日志只记录 verdict/耗时/HTTP 状态 |
| 诊断包 | 沿用 M2.1 脱敏；新增的 API 状态只含掩码与路径 |
| 修改 / 删除 | 重新输入即覆盖；"删除配置"清除密文 + 移除受管块 + 还原 `[]`，二次确认后执行 |
| 卸载 | `deleteAppDataOnUninstall: false` 保留数据；用户可在应用内先删除密钥 |

> 为什么不用 Harness 的 `.credentials.yaml`：该文件是**明文 YAML**，与 PRD「明文不落盘」冲突。选择环境变量注入后，磁盘上任何位置都不会出现密钥明文（有单测逐文件扫描 `api-service` 数据目录断言）。

## 5. 连接测试（真实请求 + 分类）

| 步骤 | 说明 |
|---|---|
| address | 解析并规范化请求地址（`/v1/messages` 或 `/v1/chat/completions`，已含 `/v1` 时不重复拼接） |
| dns | `dns.lookup` 失败即判 `dns`（不发起 HTTP） |
| request | 15 s 超时的一次 POST（`max_tokens: 16`，内容 `ping`） |
| auth | 401/403 → `auth`（含"到控制台确认 Key"的下一步） |
| model | 404 或 400 且响应提到 model → `model-not-found` |
| response | 2xx 但非 JSON / 无回复字段 → `bad-response`（**不以 HTTP 200 判成功**） |
| 其它 | 429→`quota`、5xx→`server`、超时→`timeout`、连接失败→`network` |

结果对象只包含状态、耗时、模型名与**已脱敏**的响应片段；单测断言序列化后不含密钥。

## 6. 普通用户体验

- 只有两个必填概念：**服务类型**（DeepSeek 官方 / 其它兼容 OpenAI 的服务）与 **API Key**；地址、模型都已预填。
- 明确告知：软件不提供、不代理模型服务；给出 Key 的获取路径（platform.deepseek.com → API keys）。
- 按钮语义清晰："测试连接"（不落盘）与"保存并应用"（写配置 + 回读）。
- 失败提示是"下一步做什么"，而不是错误码堆栈；分阶段结果用 ✓/✗ 展示。
- 显示配置位置与"密钥仅存本机"的说明；删除配置需二次确认。
- 全程不需要用户打开 PowerShell 或手工编辑任何文件。
