状态：草案 V0.1 · 核对日期：2026-11-02
对应 PRD：第 8 章"开源项目复用原则"、第 6 章"首批资源"、第 14 章第 2/3/4 款

## 0. 盘点口径

| 标记 | 含义 |
|---|---|
| ✅ 已验证 | 在 GitHub 源码/官方文档上直接读到，可引用 |
| ⚠️ 需核实 | 二手信息或本次被网络策略拦截，编码前必须人工复核 |
| ❌ 不可用 | 明确不可行（不存在 / 已停止维护 / 许可禁止） |

**复用方式分五档**，越靠前越优先：

`直接调用`（CLI/API） > `作为依赖` > `独立进程` > `仅参考实现` > `自研`
另有 `不采用` 一档，用于许可或维护状态不合格者。

### 1.1 关键事实（决定架构）

```text
Harness 分发：npm 包 @deepseek-ai/dsh，bin = dsh
  运行：npx @deepseek-ai/dsh web        → 127.0.0.1:3080，自动开浏览器
  插件：dsh plugin --profile <name> add <pkg>
        实现 = 把参数原样转发给 profile 目录内的 pnpm
  兼容：插件包的 engines.dsh 为 SemVer 区间
  状态：developer preview，官方声明会有破坏性变更
```

2026-11-02 二次核对补充（均为一手来源）：

```text
npm @deepseek-ai/dsh
  版本数 40；dist-tags: latest = 0.2.1-rc.5（预发布）、另有 alpha / next
  package.json 无 engines.node 声明；bin = { dsh: lib/bin.js }
GitHub Releases：仅 prerelease（dsh-v0.2.1-rc.5 / dsh-v0.2.2-alpha.2），assets = 0
  → 桌面端二进制未通过 Releases 公开分发（渠道待核实）
插件兼容字段（实测 @tencent-connect/dsh-qqbot@0.5.5）
  dsh.compatibility.dshReleases = { "0.1.0-rc.8": "compatible", "0.2.0-rc.2": "compatible" }
  dsh.bundle.patch = ./cordis.patch.yml；dsh.client.platform = web
  未声明 engines.dsh；peerDeps = @deepseek-ai/{cordis,dsh-llm,dsh-agent,dsh-session,schemastery,dsh-user-approval}
  engines.node = >=20.3.0
桌面端（apps/desktop）
  拥有 $DSH_HOME/profiles/desktop；CLI 不能启动该 profile，npm 安装的 dsh 不能修改它
  自带 pnpm（resources/runtime/primary-runtime/dependencies/pnpm），包操作不依赖 PATH
  监听 OS 分配端口（默认不是 3080）；插件管理走 Web 应用已认证的 HTTP API，无独立 IPC
```

**由此得出三条硬结论：**

1. Node.js 是 CLI 路线的硬前置 → **走 npx/CLI 的官方 QQ 模式也必须装 Node.js**（PRD 4.2 只提到"不强制 Python"，易被误读）；
   若用户走官方 Desktop 路线，则 Node 与 pnpm 由应用内置，我们**不应再装任何运行时**。
2. 插件安装的正确抽象是"封装 pnpm 调用"，**不是自研安装器**；离线安装必须落成 `.tgz` 后以 `file:` 交给 pnpm。
3. 因为 preview 会破坏兼容，**版本固定 + 三级兼容判定 + 可回退** 是 P0 需求，不是 P1；
   且"固定"必须固定到 prerelease 串（`latest` 本身就是 rc）。

## 2. QQ 接入与陪伴能力

### 2.1 官方 QQ（模式 A）— 结论：可交付

| 项 | 事实 |
|---|---|
| 协议 | QQ Bot API v2（WebSocket），**与 OneBot 无关** ✅ |
| 凭据 | `appId` + `appSecret`；也可用 `QQBOT_APPID` / `QQBOT_SECRET` 环境变量 ✅ |
| 绑定 | 手机 QQ 扫码，插件自带绑定页（`/qqbot/im-qqbot/bind`）与终端二维码两条通道；`QQBOT_BIND_OPEN_BROWSER=1` 可降级到浏览器 ✅ |
| 常用配置 | `requireMention`、`groupPrompt`、`directPrompt`、`streaming`、`historyLimit`、`access.{c2cMode,groupMode}`、`vision.enabled` ✅ |
| 平台侧 | 需在 `q.qq.com` 创建机器人并完成认证/授权（用户自行完成） |
| 版本现状 | npm `@tencent-connect/dsh-qqbot@0.5.5`（latest，共 10 个版本）✅ |
| 兼容矩阵 | 官方在包内声明 `dsh.compatibility.dshReleases`：`0.1.0-rc.8`（CLI `dsh web` 已验证扫码/手动/解绑全流程）与 `0.2.0-rc.2`（Desktop 内嵌运行时已验证端内绑定页）✅ |
| 运行时要求 | `engines.node >= 20.3.0` ✅ → 决定我们的 Node 版本下限 |

→ 我方职责边界：**装插件 + 引导到绑定入口 + 填/存凭据 + 连通性测试**，不实现协议、不实现扫码。

并在 UI 明确"暂不支持自动部署"。**PRD 6 把"已验证的网关及适配组件"列为 P0 与本结论冲突，建议在评审时降级。**

### 2.4 `qqbot-connector` 许可调查结论（M0-T10 实测）

`@tencent-connect/qqbot-connector@1.2.0` 是 `dsh-qqbot` 的**运行时依赖**（不是可选），因此"QQ 插件能否分发"完全取决于它。

| 调查项 | 结论 | 证据 |
|---|---|---|
| 发布者 | `tencentconnectqqbot`（与 `dsh-qqbot` 同一发布者），`access: public` | npm registry |
| `license` 字段 | **`UNLICENSED`** | tarball 内 `package.json` |
| LICENSE / NOTICE 文件 | **不存在**（tarball 共 14 个文件：`dist/*`、`package.json`、`README.md`） | `tar -tzf` 清单 |
| `author` / `repository` / `homepage` | 均为空 | `package.json` |
| 代码形态 | `dist` 为**混淆**产物（构建脚本含 `scripts/obfuscate.js`） | `package.json` scripts |
| 授权渠道 | README 提示商务合作走 `qq_bot_api@tencent.com` | 包 README |
| 依赖 | `qrcode-terminal@^0.12`（tarball 内为 Apache-2.0） | `package.json` |
| 商业使用 | **不可自行判定**（未授予任何权利） | — |
| 再分发 / 国内镜像 / 塞进离线包 | **不可以** | — |

**结论：许可不明确 → 不进入资源库、不打入离线包、不镜像。** 只能"运行期从 npm/npmmirror 安装"。
如需离线能力或商业分发，必须先取得腾讯书面授权（M0 §15 B2）。

### 2.3 "陪伴基础套装"逐项能力盘点（V0.1）

结论先行：**人设 / 长期记忆 / 陪聊 / 主动互动在 V0.1 都不需要新装第三方插件**，宿主已内置对应能力，缺的只是"配置 + 提示词 + 引导"。

| 能力 | 上游证据（一手） | 承载方式 | V0.1 做法 | 需第三方插件 |
|---|---|---|---|---|
| 人设 | `@deepseek-ai/dsh-persona`（`packages/preset/persona`）：preset 挂载的人设行，注册系统提示词前缀/后缀，可为会话遮蔽部署级默认值 | 宿主原生（preset 行） | 交付人设配置模板 + 预制提示词；在 profile 配置中启用该行 | 否 |
| 长期记忆 | ① 会话持久化 + `compaction` 包组（`compaction-basic` 等）为默认能力；② 官方 `docs/user/guide/mcp-memory.zh.md` 提供三份**默认关闭**的记忆 MCP 参考配置，并明确"DSH 不负责下载服务器/建库/选模型" | 原生 + 可选外部 MCP | 说明"默认已有跨会话记忆"；可选 MCP 只给配置片段与前置条件（如 `npm i -g @modelcontextprotocol/server-memory@2026.7.4`），**不代装** | 否（可选组件由用户自装） |
| 陪聊 | `dsh-qqbot` 配置项：`requireMention`、`groupPrompt`、`directPrompt`、`streaming`、`historyLimit`、`access.{c2cMode,groupMode}`、`vision.enabled` | 核心插件配置 | 配置模板 + 逐项解释 + 推荐值 | 否（复用核心插件） |
| 主动互动 | `packages/schedule` 提供 RFC 5545 计划任务与 `schedule_*` 工具；**但 M0 实测 `dsh@0.2.0-rc.2` 的 web profile 未挂载该行**（配置中无 `- id: schedule` / `tool-schedule`，包虽随宿主安装但不生效） | 宿主原生（需挂载） | V0.1 标注"**默认不可用**"；如需启用须先验证手工挂载 `dsh-schedule` + `dsh-tool-schedule` 行（未验证） | 否 |

**因此"核心插件套装（A 方案）"的边界是：`@tencent-connect/dsh-qqbot` 一个插件 + 一组配置/提示词产物。** 不引入人设/记忆/陪伴类第三方插件，避免把"未经验证的生态"塞进 V0.1。

| 项目 | 许可 | 复用方式 | 说明 |
|---|---|---|---|
| Node.js 官方发行版 | MIT ✅ | `直接下载` | `nodejs.org/dist/vX/node-vX-win-x64.zip`（同目录有 `SHASUMS256.txt`、`index.json`）→ 可便携解压，免管理员；**本产品下限 20.3.0**（由 dsh-qqbot 的 `engines.node` 决定，dsh 本体未声明 `engines.node`）；核对日 LTS 线为 26.13.0 / 24.22.2 / 22.23.4。**V0.1 固定 22.23.4**（`node-v22.23.4-win-x64.zip`，35,604,229 B，sha256 `cbc74b5e…5f20` 已实测；与 Desktop 内置 Node 22 同线，原生模块预编译更稳），24.22.2 列为待验证备选 |

| Git for Windows | **GPL-2.0** ⚠️ | `直接下载`（不预置） | PortableGit `.7z.exe` 可随包但要满足 GPL 义务；**建议运行期下载 + 默认不装** |

| WinGet | MIT ✅ | `直接调用 CLI` | 依赖 App Installer（Win10 1809+），Server/精简版常缺失；`cdn.winget.microsoft.com` 国内不稳；多数包需 UAC |
| Scoop | Unlicense/MIT ✅ | `直接调用 CLI` | 天然免管理员（装 `%USERPROFILE%\scoop`），bucket 走 GitHub，国内需镜像（⚠️ 镜像现状待核实） |

包管理器**绝不打包进安装包**。

## 5. 复用决策总表

| 能力 | 决策 | 依据 |
|---|---|---|
| Harness 本体 | 不打包、不集成、仅 CLI 调用 | PRD 2.2 / 14 第 6 款；MIT 但定位不允许 |
| 插件安装 | 封装 `dsh plugin` CLI | 官方唯一文档化接口 |
| 插件市场 UI | 不新建，产出 DSH 兼容 index | index format 已覆盖标题/图标/作者/版本/兼容区间 |
| 索引结构校验 | **`作为依赖`复用 `@deepseek-ai/dsh-plugin-market-index`** | 官方即唯一规则来源；首条违规抛错 → 整份拒绝 |
| 插件安装规格 | 复用其 `marketInstallTarget()` 生成 `{ spec, registry? }` | 避免自行拼接 `name@ver` / `git+…#commit` 出错 |
| 官方桌面端 Desktop | 只检测与引导，不代下、不代装、不镜像 | 其载荷 ≈588 MB 由官方 CDN 分发；profile 对 CLI 封闭；PRD 亦排除自研桌面端 |
| 版本组合 | 只认 `manifests/harness/compat.json` 白名单，禁止 dist-tag | `latest` 即 prerelease；qqbot 只列特定宿主版本 |
| 索引托管 | 官方校验库 + 本地 HTTP 索引注册进 profile `indexes` | `indexes` 只接受 http(s)；离线用户也可在"发现"页看到策展清单 |
| 陪伴能力 | 原生能力 + 配置 + 提示词，不引入第三方陪伴插件 | dsh-persona / schedule / compaction 均已内置（§2.3） |
| Node.js 版本下限 | 20.3.0（取插件最严要求），V0.1 固定 22.23.4 | dsh-qqbot `engines.node >= 20.3.0` |
| QQ 官方接入 | 复用 `@tencent-connect/dsh-qqbot` | 腾讯官方、MIT、自带扫码 |
| QQ 个人接入 | 仅留 Port + 桩 | 无合规可预置网关 |
| 运行时安装 | 官方发行包 + 自管目录 | 免管理员、可回收 |
| 包管理器 | 仅 fallback | UAC 与国内网络风险 |
| 下载/校验 | 自研精简（约 300 行）+ Node `crypto` | 无合适现成库 |
| 解压 | yauzl + 7za | 成熟、MIT/LGPL |
| 安装器 | electron-builder + NSIS | 与 electron-updater 原生集成 |
| Agent 框架 | 自研（仅编排逻辑，不含 LLM/Agent） | 这不是"重建 Agent"，是部署编排 |

## 6. 许可合规清单（分发前必查）

1. **MIT/Apache/ISC/PSF/Unlicense**：随包附版权声明与许可全文即可（`resources/licenses/`）。
2. **GPL-2.0（Git PortableGit、LLBot）**：不得与我们的闭源代码静态链接；若仅"聚合分发"独立可执行文件，须附许可全文与源码获取方式。**建议不预置。**
3. **AGPL-3.0（AstrBot、go-cqhttp）**：作为独立进程通过 HTTP/WS 通信通常不构成衍生作品，但**随包分发二进制须附对应源码**，风险高 → 不采用。
4. **NapCat 自定义许可**：明文禁止商业使用 → **绝对不得预置、不得作为卖点功能**。
5. **FFmpeg**：必须选 `lgpl-shared` 变体，避免 x264/x265 等 GPL 组件。
6. **Harness preview**：MIT 允许商用，但需在用户手册中提示"上游为 developer preview，可能破坏性变更"。
7. **商标**：产品名与图标不得使用 DeepSeek / 腾讯的商标或官方视觉标识；文案用"支持 DeepSeek Harness"而非"DeepSeek 官方"。
8. **`UNLICENSED` / 无 license 字段的依赖视为不可再分发**（详见 01 §11.6）。
   当前命中：`@tencent-connect/qqbot-connector@1.2.0`（`dsh-qqbot` 的运行时依赖，npm 元数据 `license: UNLICENSED`），
   其上游 `@tencent-connect/qqbot-nodejs@1.0.5` 为 MIT。
   → **含该依赖的完整离线包在许可澄清前不得随包分发**；离线能力只能做到"插件本体 + 许可清晰依赖"，其余依赖需运行期解析。
   → 需在 M0 向腾讯 connect 团队书面确认，或改用"在线安装"作为 QQ 插件的唯一分发方式。
9. **离线包的许可判定必须基于依赖闭包**，不能只看顶层包：`pnpm list --prod --depth Infinity` 的结果逐项过 `license-gate`，任一命中即阻止打包。
10. **元数据缺失不等于无许可**（M0 实测）：`qrcode-terminal@0.12.0` 的 npm 元数据**没有 `license` 字段**，但 tarball 内含 Apache-2.0 全文。
    → 门禁必须"元数据优先，缺失则回退读取 tarball/LICENSE 文件"，否则会误杀合规依赖。
11. **`Python-2.0`（如 `argparse@2.0.1`）不在默认允许清单**，需逐条 allowlist（附 reviewer/rationale），不得默认放行。
