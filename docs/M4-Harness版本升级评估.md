# Harness 版本升级评估与验证

日期：2026-11-05；产品开发版本：0.1.1。用户明确要求升级 Harness 以提高插件兼容性。

## 决策与边界

从 `0.2.0-rc.2` 升至固定版本 `0.2.1-rc.3`，Node `22.23.4`、pnpm `11.28.5`、官方 QQ 插件 `0.5.5` 不变。个人 QQ 适配插件 `dsh-qq-link@1.5.1` 上游明确声明支持 `0.2.1-rc.3`，大肥鱼陪伴插件文档也以该版本为验证基线，dsh-pet 声明支持该版本。无声明的插件不能因此视为兼容；插件许可、安装和运行各自独立判断。

官方 QQ 插件 `0.5.5` 的上游声明只列 `0.1.0-rc.8` 与 `0.2.0-rc.2`，**未声明兼容 `0.2.1-rc.3`**。本轮本地初步测试可启动并产生授权入口，但不能据此声称上游支持或真实收发已通过。

## 隔离验证

- Windows x64、Node `22.23.4`；镜像直连，移除代理环境变量，新目录与独立 pnpm store，关闭安装脚本。新宿主安装完成，`--version` 输出 `0.2.1-rc.3`。
- 独立 web profile：`@tencent-connect/dsh-qqbot@0.5.5` 安装和列表可见、组合配置包含插件，进程启动并产生绑定入口；HTTP 401 只能证明服务存活。未扫码、未验证 QQ 收发。
- 另一个独立 web profile：`dsh-qq-link@1.5.1` 安装成功，进程启动，状态接口可访问但未连接真实 OneBot，未验证个人 QQ 收发。
- 用旧版 Harness 在空目录生成测试 profile 并添加合成标记；新版运行插件列表后，该测试 patch 文件的 SHA-256 未变化。这不代表所有用户已有插件、配置、会话都已迁移验证。
- 现有 web profile 在本软件部署准备步骤修改前，先备份依赖、锁文件和 patch 到本软件备份目录；不备份或覆盖 Desktop profile，不删除旧版 Harness 或用户会话。备份不等同于完整迁移回滚，真实旧用户环境仍待验收。

## 项目回归

- `npm run verify`：655 项通过、6 项跳过；类型、许可与声明检查通过。
- `npm run build`、`npm run build:index`、`npm run validate:index` 均通过。
- 现有机器只安装旧版本软件管理的 Harness 时，环境检测会将新版本判为待安装；新旧运行目录分开，旧运行目录不会被删除。已有 profile 将在新部署修改前备份，但完整升级和恢复仍需真实用户环境验收。

## 未完成

- 未进行真人授权、官方 QQ 群聊/私聊、个人 QQ 或模型 API 全链路测试；QQ 门禁状态不变。
- 未对所有高关注度插件逐一执行安装、功能及许可测试，不能宣称“大部分插件均可用”。
- 历史候选审计文件中的安装探测针对旧版 `0.2.0-rc.2`，不得当作新版证据；部分其他候选的旧版说明保留为历史记录。
- 已交付的 V0.1 安装包不含本次改动；需重新构建并独立验证后才能交付 V0.1.1。
